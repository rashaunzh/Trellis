# 2026-08-20 Trellis V0.2：匿名 owner 隔离（demo anonymous workspace isolation）

## 背景

公网部署完成后（https://trellis.rashaunzh.workers.dev），发现 `ownerOf()` 固定返回 `DEFAULT_OWNER`——公网上所有访问者共享一个学习状态，互相覆盖、可被"重新设置"清空。用户拆解问题三层（能不能安全演示 / 稳定访问 / 证明产品价值），决策：先做最小匿名隔离（不是鉴权），再进 P0。

## 实现（3 个文件 + 1 个测试 + 1 个脚本）

1. `app/api/learning/_shared.ts`：`ownerOf(request)` 优先读 `x-trellis-owner-id` header，正则 `/^[A-Za-z0-9_-]{8,128}$/` 校验，无/非法回退 `DEFAULT_OWNER`。
2. `lib/learning/frontend.ts`：`getOwnerId()`（localStorage key `trellis.anonymousOwnerId`，`crypto.randomUUID()` 生成，SSR 无 localStorage 返回空）+ `apiFetch()` 统一注入 header；13 处 `fetch(` 批量替换为 `apiFetch(`（sed）。
3. `tests/learning-domain/owner-isolation.test.ts`：7 个新测试——ownerOf 单元 3 个（header 优先/无 header 回退/非法格式回退）+ service 层多 owner 隔离 4 个（诊断不互串/周计划不影响/reset 只清当前/replan 只重排当前）。
4. `scripts/acceptance-replan.py`：修复——页面请求现在带 localStorage ownerId，脚本 API 快照必须用同一 owner，否则快照落在 DEFAULT_OWNER。注入固定 `OWNER_ID = "acceptance-owner-0001"`（add_init_script + api 请求 header）。

## 关键发现（隔离生效的实证）

前端改动后首次跑验收脚本 30/32：UI（浏览器带 UUID header）5→9 活动正常，但脚本 API 快照（无 header → DEFAULT_OWNER）还是旧 9 活动 → "新增活动=0"。**这正是隔离生效的直接证据**：UUID owner 和 DEFAULT_OWNER 两个状态共存、互不干扰。修复脚本统一 owner 后 32/32 恢复。

## 设计边界（用户定义）

- 是匿名隔离不是鉴权：换浏览器/清缓存丢状态、ownerId 可伪造、无安全意义。
- 不做真鉴权（Clerk/Auth0/session 全部排除）；不改数据模型；不破坏 DEFAULT_OWNER fallback。
- 每个浏览器独立状态：演示对象打开后是自己的空状态。
