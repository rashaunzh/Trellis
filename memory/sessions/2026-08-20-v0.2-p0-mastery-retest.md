# 2026-08-20 Trellis V0.2：P0 掌握确认 + 延迟复测（CP-C / CP-D）

## 背景

工程可用 MVP 完成后，按 P0 计划推进剩余两项产品价值缺口：掌握确认（系统判断 → 用户确认/纠正 → 状态写入）与延迟复测（一次通过 ≠ 永久掌握）。

## 掌握确认（P0-C）

- `NODE_STATUS` 增加 `pending_confirmation`（成长页四色：灰/黄/紫/绿）。
- 状态机新事件：`pendingConfirmation`（growing→pending_confirmation）、`confirmMastery`（→validated）、`correctMastery`（→growing）。
- `nodeEventOfEvidence(evidenceStatus, { requiresConfirmation })`：综合任务/复测驱动的**首次验证**需确认（节点非 validated 时），普通活动保持自动验证（向后兼容，51 个旧测试零破坏）。
- `POST /api/learning/nodes/:id/confirm-mastery`（decision: confirmed|corrected, note?）：
  - confirmed → validated + confirmedAt + mastery_confirm(accepted) 调整记录
  - corrected → 回 growing + confidence 降 1 + mastery_confirm(rejected) + weekly_light(proposed) 补强建议
- `ADJUSTMENT_TYPES` 增加 `mastery_confirm`。
- node_progress 新列：confirmed_at（迁移 0009）。
- 前端：成长页四色图例 + 节点详情"确认掌握/纠正"按钮；CSS st-pending_confirmation（紫 #8e5bc9）。

## 延迟复测（P0-D）

- `ACTIVITY_TYPES` 增加 `retest`；composer 增加复测模板（脱离材料回答验证题）。
- node_progress 新列：review_interval_days（默认 14）/next_review_at/review_count（迁移 0009）。
- workspace 聚合 `dueReviews`：validated 且 nextReviewAt 到期（或 lastValidatedAt+间隔已过）。
- `POST /api/learning/nodes/:id/retest`：生成 retest 活动（isCore=false，不计承诺）。
- 评估分支：复测 accepted → 节点保持 validated（不重复确认）+ nextReviewAt 顺延（间隔翻倍 14→28→56）+ reviewCount+1；needs_revision → 节点 evidenceInvalidated 回 growing + confidence 降 1。
- 修复：startActivity 对 validated 节点不触发 beginLearning（复测活动开始不降级）。
- 前端：学习页"复测提醒卡"（dueReviews>0，点击生成复测活动）；成长页节点"待复测"badge。
