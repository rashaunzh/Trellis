# 产品设计会话摘要

## 本次完成

- 将产品定名为 Trellis。
- 固化四条主线及其边界。
- 梳理学习成长八阶段路线和 AI 产品经理求职六阶段路线。
- 明确商业探索的三个当前方向。
- 确定 Obsidian/Hermes、NotebookLM/Gemini/ChatGPT、Codex 与 Trellis 的分工。
- 确定星级、周看板、阶段状态、任务字段和概念闪卡规则。
- 决定以私有 Git 仓库承载 V0.1 代码与记忆。
- 制定 AI 提案确认协议和跨电脑 handoff 协议。

## 用户核心问题的结论

- 不需要为了记忆微调模型；Instructions + 结构化仓库记忆 + 按需上下文足够验证 V0.1。
- 不需要把所有外部对话完整导入；保留链接、关键结论、依据、分歧与下一步。
- MCP 是未来降低摩擦的接口层，不是启动 Trellis 的前置条件。
- 日历可以以后作为视图或接口，但当前以区间承诺和实际完成记录为主。
- 任务多显示是为了建立长期方向感，承诺数量仍需受周容量限制。
