# 2026-09-03 学习处境编排重构

## 背景

用户连续指出当前 Trellis 过度停留在“课程组合”和“材料分拣”，没有真正回答新手进入学习系统时的核心问题：我是谁、我现在该学什么、为什么先学这些、学完如何知道自己变强、材料和外部信息如何进入学习闭环。

本轮目标不是新增第四个主页面，也不是继续扩 Agent 架构，而是把现有 Course Intelligence 能力重新投影为更正确的产品语义。

## 已完成

- 新增 `LearningOrchestrationState` 读模型，把现有课程智能、学习状态和用户资源组织为学习处境、本周任务包、能力模型和学习控制台。
- 零材料用户被识别为 `zero_material` 起点诊断，不再默认解释为材料过载。
- 本周学习从课程主线改为能力任务包：任务标题优先使用能力/知识点，课程名降级为来源片段。
- 新增语义化 API：处境诊断、来源分流、任务包生成、测评提交和成果评审；内部复用现有服务，不引入新数据库迁移。
- 学习页改为“判断学习处境 / 本周只做一件事 / 能力任务包”，不再把课程方案作为第一层叙事。
- 成长页新增路径分叉与能力模型视图，明确“走到路径深处不等于能力等级高”。
- 工作台改为学习控制台雏形：来源中心、测试机、成果陈列室，而不是杂物收纳区。
- 新增高可信参考基线文档，沉淀 Khan Academy、Duolingo、Coursera Skills Graph、Open edX、Moodle、Canvas、H5P、Anki/FSRS、OATutor/pyBKT、Linear、Notion、Readwise、GitHub Review、Figma Dev Mode 等可借鉴机制。
- 补充领域测试，覆盖零材料入口、任务包投影、来源中心、测试机和成果陈列室。

## 验证

- `npm run typecheck` 通过。
- `npm run test:domain` 通过，241 项领域测试。
- `npm run check` 通过，包含 typecheck、lint、秘密扫描、迁移链、领域测试、生产构建和 rendered HTML 契约。

## 当前限制

- 本轮优先做语义读模型和 UI 投影，没有新增持久表；来源分流、测评计划和成果状态仍主要由现有数据投影得出。
- `Course Intelligence` 仍作为内部兼容名存在，部分旧组件和旧文档还需要继续改成“学习编排 / 能力任务包”语义。
- 尚未接入真实 FSRS/BKT 或外部课程解析工具；当前只是保留测评与复习调度的位置。
- 本轮未重新跑浏览器视觉验收截图；需要下一轮检查 `/learn`、`/grow`、`/workbench` 的桌面与 390px 手机端。
- 仍未公开部署；生产发布继续受远程 D1、secrets、ChatGPT 托管身份和线上 smoke 阻塞。

## 下一步

1. 做浏览器视觉验收，尤其检查学习页旧“课程方案/路线管理”残留、手机端排版和成长页路径图可读性。
2. 清理旧文案与旧组件，把 Course Intelligence 的外显语义统一为学习编排。
3. 将来源中心、测试机、成果陈列室从投影视图升级为可持久追踪对象。
4. 选择是否引入 `ts-fsrs`、H5P/xAPI 或轻量 BKT，用于真正的课后检查与复习调度。
5. 再做一轮真实 AI PM 与非 AI 领域用例走查，确认系统没有过度拟合 AI 产品经理学习。
