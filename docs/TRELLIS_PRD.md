# Trellis 产品骨架（V0.1）

> Trellis 是个人成长与行动中台。它不替代知识库、阅读工具或通用 AI，而是维护路线、任务、证据、决策与连续记忆。

## 1. 当前目标

先让一条真实链路跑通，再决定是否扩建：

1. 在四条主线下看见长期路线与当前任务。
2. 从任务进入外部工作台完成学习或创作。
3. 把疑问、AI 讨论、结果和证据回写 Trellis。
4. 通过一周重点验证与连续两周真实使用，决定是否进入 V0.2。

首条验证链路是 **Notebook 测评项目**：选定资料 → 在 NotebookLM/Gemini 中阅读问答 → 形成评价框架 → 输出作品 → 保存证据 → AI 复盘 → 调整路线。

## 2. 四条主线

| 代码 | 主线 | 作用 |
|---|---|---|
| G | 学习成长 | 建立计算机、AI、Agent 与产品化能力 |
| J | 求职发展 | 从目标岗位与 JD 倒推能力、作品证据和求职动作 |
| B | 商业探索 | 验证内容渠道、产品机会与可持续商业模式 |
| I | 创新与想法 | 保存值得判断的想法，并决定进入哪条主线 |

学习与求职是当前需要维护完整路线图的核心主线。商业探索当前包含 X + 小红书、短视频/抖音、能源平台三个方向；能源平台先按产品项目管理。想法入口与 Obsidian/Hermes 的信息流 Inbox 共用，不在 Trellis 重建剪藏器。

## 3. 信息结构

```text
主线
└── 路线 / 阶段 / 能力节点（描述成长顺序）
    └── 项目（以交付结果为边界，可跨主线）
        └── 任务（最小可执行动作）
            ├── AI 讨论
            ├── 来源链接
            └── 证据 / 作品
```

关键定义：

- **阶段不是项目**：阶段表达“先学什么、后学什么”；项目表达“要交付什么”。
- **作品不是第五条主线**：作品是学习、求职、商业共享的证据对象。
- **微习惯不是功能类型**：它是任务设计原则——足够小、能立即开始、完成后有反馈。
- **概念卡是闪卡**：用于学习记忆，可在以后导出 Anki。

## 4. 计划模型

### 4.1 用户可见状态

- 进行中
- 短期启动
- 长期规划
- 暂停
- 完成
- 待确认（仅用于 AI 提案）

“短期”和“长期”表达承诺距离，不强制绑定某一天。周看板只约束区间结果，例如“一周健身四次”，记录第四次在第几天完成。

### 4.2 时间预算

- 0.5 星 = 15 分钟
- 1 星 = 30 分钟
- 每增加 0.5 星，增加 15 分钟
- 星级是启动前的粗估；完成后记录实际用时
- V0.1 不内置实时计时器

### 4.3 任务最小字段

每项任务至少说明：

- 做什么
- 为什么现在做
- 所属主线、路线阶段与顺序
- 前置条件
- 下一步动作
- 预计星级
- 完成标准与预期证据
- 核心资料链接
- 实际用时与复盘（完成后）

界面应展示足够多的后续任务，使用户看见长期方向；但一周内只承诺少量重点。

## 5. 工具边界

| 系统 | 职责 |
|---|---|
| Trellis | 路线、任务、关系、决策、证据索引、连续记忆 |
| NotebookLM / Gemini | 基于资料的阅读、问答与学习工作台 |
| ChatGPT | 讨论、解释、规划与综合推理 |
| Codex | 仓库、代码、结构化记忆与执行 |
| Obsidian / Hermes | 信息流 Inbox、剪藏、批处理、知识原文 |
| Anki（以后） | 闪卡复习 |

Trellis 保存链接、摘要、结论和下一步，不复制外部工具的全部内容。

## 6. AI 原则

- 模型中立；V0.1 不依赖付费 API。
- “与 AI 讨论”是每个对象的上下文能力，不是独立页面。
- 不用微调保存个人记忆。
- AI 可以读取上下文、解释安排、拆分任务、总结讨论并提出修改。
- 所有写入先成为 **提案**，由用户确认后进入正式记忆。
- 未来通过 MCP 暴露读取上下文、生成提案、确认写入等能力。

## 7. V0.1 验证标准

一周检查重点是否成立，两周判断是否继续建设。至少观察：

- 是否能从路线无困惑地选出下一项任务
- 小任务是否更容易启动
- “为什么做”和前后顺序是否减少迷失
- 外部 AI 讨论能否低摩擦沉淀
- 证据是否能同时服务学习与求职
- 周计划是否在不排死日历的情况下完成
- 维护 Trellis 的成本是否低于它节省的决策成本

在真实使用数据出现前，不自动扩建 V0.2。
