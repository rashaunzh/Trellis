## 记录规则

- 每条记录必须来自一次真实操作或可复现验收，不写纯推测。
- 用户卡点优先于正面描述；没有卡点不代表通过。
- 每条结论必须落到保留、修改、删除、延后四类判断之一。
- 截图、脚本输出和 API 状态可以作为证据，但不能替代人工观察。

## 测试者维度

首轮至少覆盖三类内部测试身份：

- 产品所有者：验证目标、路线和取舍是否符合真实学习意图；
- 冷启动观察者：验证首次进入是否能理解；
- 中断回访者：验证恢复状态、暂停原因和反馈变化是否降低重启成本。

## 自动验收基线

### 2026-09-02 / 自动脚本 / 5 条剧本骨架

- 用户目标：判断 Agent 产品场景，设计能力边界、人工兜底和最小评测方案。
- 原替代方案：直接浏览 DeepLearning.AI 课程目录，再用笔记工具手动记录进度。
- 实际路径：目标输入 → 有限课程组合 → 路线确认 → 当前片段 → 开始/暂停/补定位 → 反馈变化 → 成长页 → 工作台附加。
- 成功点：脚本可验证路线有限、来源精度、恢复状态、反馈变化、工作台上下文和移动端基础可用。
- 卡点：自动脚本无法判断文案是否被真实用户理解，仍需人工记录。
- Trellis 保存或恢复的状态：课程组合、活动状态、暂停原因、用户补充定位、实际用时、学习信号、资料附加关系。
- 产品判断：保留三页结构，下一轮通过人工内测决定是否微调文案和路线管理入口。
- 下一步改动：执行至少 5 次人工内测记录后更新 Case Study。
