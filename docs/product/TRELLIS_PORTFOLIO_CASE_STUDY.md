# Trellis 作品集 Case Study

更新日期：2026-09-02
状态：中高级 PM 作品集内测版

## 一句话定位

Trellis 是面向 AI / AI PM 初学者的连续学习编排系统。它不替用户生产更多课程内容，而是把目标、已有课程、路线取舍、当前片段、反馈信号和成长状态连接起来，让用户中断后仍能继续，并知道路线为什么变化。

## 背景问题

AI 学习者通常不是缺课程，而是同时遇到四类断裂：

- 内容断裂：课程、文章、视频和工具越收越多，但不知道哪段现在值得看；
- 行动断裂：一次生成的学习计划很快失效，用户回来时不知道从哪里继续；
- 信任断裂：系统能说章节，却常常没有准确 URL、时间戳或可打开位置；
- 成长断裂：看过、收藏过、聊过很多内容，但没有沉淀为可解释的能力信号。

普通计划工具擅长列表和日期，通用 AI 擅长即时回答，课程平台擅长内容交付。Trellis 的切入点是中间缺失的一层：持续维护学习判断。

## 目标用户

首期用户是 AI / AI PM 初学者，尤其是：

- 想理解生成式 AI、Agent、AI 产品边界和评估；
- 已经收藏了课程或资料，但无法判断采用顺序；
- 每周时间有限，需要有限组合而不是完整课表；
- 学习经常中断，需要恢复状态；
- 希望看到系统为什么调整路线，而不是被自动改路。

## 产品洞察

Trellis 的核心洞察：

> 用户需要的不是“再推荐一门课”，而是“把当时为什么这么学、学到哪、后来为什么改”保存下来。

因此产品重点不是内容生成，而是：

- 有依据的课程取舍；
- 准确或诚实的来源定位；
- 可恢复的当前片段；
- 可解释的反馈后变化；
- 基于证据的成长状态；
- 工作台资料与学习上下文的轻量闭环。

## 方案

Trellis 保持三个一级页面：

- 学习：回答今天继续什么、路线为何变化、下一周提案；
- 成长：回答当前阶段、目标能力、已获得信号、下个里程碑；
- 工作台：承接辅助工具、暂存内容和外部知识库链接。

路线管理不进入主导航，而是学习页内的二级面板。这样用户日常打开 Trellis 时先看到当前片段，不被完整路线和后台对象打断。

## 核心闭环

1. 用户输入目标和已有课程；
2. Trellis 生成有限课程组合，区分主线、选定章节、补充、暂缓和排除；
3. 用户确认路线后进入当前片段；
4. 点击来源只记录开始，不冒充完成；
5. 用户可暂停、恢复或补充准确位置；
6. 用户提交轻反馈、课程原测试或情景判断；
7. 系统更新学习信号、实际用时和后续动作；
8. 成长页只展示真实能力信号，不把计划中节点当成长；
9. 工作台资料可附加到当前片段，作为辅助上下文而不是路线决策。

## 关键取舍

- 不做第四主页面：路线管理重要，但不是用户每天打开产品的第一心智。
- 不展示多 Agent：后台可以有工作流，前台只暴露一个连续学习系统。
- 不做课程市场：首期问题是课程过载，不是课程不足。
- 不做打卡和日历：Trellis 关注周内可完成行动，不争夺日程工具职责。
- 不复制外部知识库：NotebookLM、Obsidian、Feishu 继续负责深度材料，Trellis 保存学习相关状态、关系和链接。
- 不把完成等同掌握：成长必须来自反馈、测验、情景判断或作品证据。

## 当前证据

已实现并可本地验收：

- Course Intelligence：课程目录压缩、章节映射、取舍理由和缺口暴露；
- Learning Continuity：开始、已打开未反馈、暂停、恢复、完成和实际用时；
- Source Resolution：准确章节、课程主页、缺失位置和个人补定位；
- Adaptation Timeline：反馈后的变化可跨刷新查看；
- Growth Path：当前阶段、能力信号、下一里程碑和验证方式；
- Workbench Context：资料附加到当前片段或节点，不改变课程取舍；
- Mobile Baseline：390px 主学习动作、导航和无严重横向溢出。

自动验证：

- `npm run check`
- `npm run acceptance:course-intelligence`
- `npm run acceptance:internal-test-loop`

本轮产品切片进一步把“学习任务”从课程标题提升为能力任务契约。每个任务现在会解释能力问题、当前优先级、学习方式、预期结果、出口检查、停止条件、失败后的动作和它在成长路径中的意义；反馈提交后会立即生成学习结果、能力信号和下一步调整总结。学习页同时保留可展开的决策依据，展示处境判断和本周优先级来自哪些输入以及当前置信度。

## 内测方法

当前不急于公开测试。下一阶段先执行内部测试闭环：

- 首次进入与路线确认；
- 开始学习与来源定位；
- 中断恢复；
- 反馈后变化可见；
- 工作台资料引用。

每次内测记录用户目标、原替代方案、实际路径、卡点、系统保存或恢复的状态、产品判断和下一步改动。

## 中高级 PM 价值

这个案例重点体现：

- 能从真实使用断点重定义问题；
- 能克制信息架构，不把所有后台能力变成功能入口；
- 能处理 AI 产品的信任边界；
- 能把学习行为建模为状态、证据和决策；
- 能先做内部验证，再决定是否生产发布；
- 能在工程约束下保留可测试、可回归的产品闭环。

## 当前不足

Trellis 还不是公开生产级产品：

- 远程 D1 迁移和线上 smoke 尚未执行；
- ChatGPT 托管身份和生产 secrets 尚未联调；
- 缺少真实人工内测记录；
- 缺少用户卡点驱动的迭代前后对比；
- 缺少最终作品集讲述截图编排。

因此当前定位是：中高级作品集内测版，而不是公开生产版。

## 最近一轮实现证据

当前学习页已从“当前课程片段”推进为“能力任务包”：每周围绕一个能力结果组织核心与可选任务，明确顺序、完成标准和停止条件。单项反馈会形成可回读的任务结果，说明本次接触的概念、证据强度、尚未证明的部分、能力状态变化和下一步理由。该结果通过 `LearningTaskResult` 读模型从已保存事实重新计算，刷新后仍可获得。

这轮实现证明了产品闭环的一个关键转变：学习反馈不只是一次提交动作，而是影响能力证据和后续决策的持久事实。它仍不是完整 PR 的结束，内容拆解与工作台对象化必须经过人工内测后继续推进。

随后新增的来源对象把外部材料从临时链接提升为可追踪对象：来源先进入收集状态，规则版分析生成候选片段，用户确认后才成为可用于学习判断的来源。系统保存来源版本、能力映射、置信度和待解决问题，避免“只有一个课程链接却假装已经定位到具体知识点”。
