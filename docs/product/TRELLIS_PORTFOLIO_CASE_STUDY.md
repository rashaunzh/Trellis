# Trellis 作品集 Case Study

更新日期：2026-08-30

## 一句话定位

Trellis 是面向 AI / AI PM 初学者的学习内容整合与低启动行动系统。它不继续增加课程推荐，而是判断资料是否专业、切出此刻该看的课程片段、生成本周最值得推进的几步，并用轻反馈形成连续周记忆。

## 问题

AI 学习者通常不是缺课程，而是课程太多、术语太密、路径太平铺。普通学习计划工具把材料排成待办，默认用户知道什么重要、什么先跳过、怎么判断自己学会；真实情况是初学者往往无法表达困惑，也不愿把中间过程写成长作业。

Trellis 要解决的是确定性启动问题：当用户手上有课程和任务时，系统告诉他本周只看哪几段、为什么现在看、看完做一个什么轻动作，以及哪些高阶内容先别碰。

## 用户

当前 MVP 聚焦 AI / AI PM 入门用户：

- 有学习意愿，但目标、材料和能力状态不稳定；
- 手上已有课程、文章、视频目录或项目资料；
- 需要从内容过载中切出本周行动；
- 不希望每次学习都被迫写长总结或交正式作业；
- 希望学习状态能跨周积累，而不是刷新后回到空白。

## 产品判断

Trellis 的差异化不在“生成更多内容”，而在“判断与取舍”：

- 课程推荐不是第一优先，因为用户通常已经有太多课程；
- 外部 AI API 是增强项，不是基本依赖；
- 初学阶段不默认强作品，作品是可选阶段路径；
- 轻反馈优先于强证据，避免学习系统变成另一个做作业的地方；
- 概念解释默认折叠，用户点击才展开，减少术语轰炸。

## 核心方案

1. Learning Situation：先识别目标、资料、时间容量、精力状态、行为模式和证据状态。
2. Material Intelligence：判断材料专业性、阶段适配和当前用途。
3. Course Slicer：把课程目录、视频目录、文章目录或摘要切成多个片段。
4. Weekly Action：只采用少数本周必看片段，生成 30 分钟起步、15 分钟递增的行动卡。
5. Light Feedback：用深度选择、状态选择、三句话判断或随堂测试结果留下学习信号。
6. Week Review：把完成情况、轻反馈、退回修订、材料错配和容量变化汇总成下周计划依据。

## 与其他路线的区别

OpenMAIC 一类产品更像 AI 生成的互动课堂或学习内容平台，优势是内容生产和课堂体验。Trellis 更像学习者身边的课程分诊与行动编排层：它默认用户已有外部课程，重点不是替代课程，而是判断哪段现在值得看、怎么轻启动、如何跨周调整。

普通计划工具关注日期、列表和完成率。Trellis 关注材料取舍、能力节点、轻反馈、掌握确认和下周生成。完成一项任务不自动等于掌握，短反馈也不会被浪费，而是进入学习记忆。

## MVP 边界

已纳入：

- AI / AI PM 入门内容包；
- 手动粘贴课程目录、摘要或关键片段；
- 规则版课程切片、行动卡、轻反馈、周复盘和三周验收；
- 无模型 Key fallback；
- D1 / service / read model 架构。

暂不纳入：

- 账号系统、社交、课程市场；
- 自动抓取完整视频、PDF 或字幕；
- 向量记忆和复杂权限系统；
- 完整 autonomous agent runtime；
- 外部 AI 强依赖。

## 交付叙事

3 分钟 demo 应聚焦一条线：贴课程目录，Trellis 判断专业性并切片，本周只采用少数关键片段，用户打开 `/learn` 只看到本次行动、本周只看和待处理，完成轻反馈，周复盘生成下一周。作品任务和系统状态作为补充展示，不抢主线。

## 交付状态

交付前最后两轮不再扩核心能力，而是收敛可用性和可展示性：

- Round 4 将 `/learn` 第一屏压成三块焦点视图，完整行动卡、材料取舍、学习产出、作品闭环和系统状态都下沉或折叠。
- Round 5 增加生产 smoke 与交付预检查，保证线上 demo、三周验收截图、case study、demo script、架构说明和部署说明能够一起交付。
