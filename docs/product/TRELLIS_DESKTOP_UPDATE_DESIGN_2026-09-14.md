# Trellis 桌面端更新设计报告

日期：2026-09-14
文档性质：待审阅的详细交互设计，供下一版实现使用；不是失败报告，也不是已上线功能说明。
已确认的本轮要求：具体到每次点击；桌面端先完成，手机端开发滞后。
设计基于：本轮当前版本实物走查、现有能力与第三方官方设计资料。未采用历史评审结论。

## 1. 下一版交付什么

下一版让用户围绕同一条学习路线，完成以下连续操作：

**说明目标 → 添加可选材料 → 看懂并采用路线 → 开始一个活动 → 返回记录结果 → 继续下一项 → 必要时调整路线。**

不要求用户理解“处境、任务契约、学习信号、来源分诊”等系统内部名词。

桌面端保留三个一级导航：**学习、成长、工作台**。不增加“今日”、日历、打卡或实时计时器。现有三个页面的职责重新明确：

| 页面 | 用户来这里做什么 | 页面唯一的主要对象 |
|---|---|---|
| 学习 | 决定这周做什么，开始、继续和反馈 | 本周学习活动 |
| 成长 | 看长期方向、当前阶段和已有成果 | 我的路线 |
| 工作台 | 添加、理解和管理学习材料 | 我的材料 |

检查属于具体活动，结果属于对应的活动和能力；材料可以从多个入口添加，但最终管理的是同一份材料，不创造平行材料库。

### 1.1 本轮实现范围

必须完成：首次设置、路线审阅、学习首页、活动详情、外部学习返回、四类反馈、材料列表与详情、路线概览、路线调整预览、周复盘、错误与中断恢复。

暂缓：独立教学平台、自动批改开放作品、更多领域、排行榜、复杂能力雷达、新外部工具集成、手机专项布局。

桌面优先并不表示可破坏现有小屏访问：保留基本响应式和可操作性；手机专项导航、抽屉手势、手机视觉与完整适配在桌面闭环验收之后交付。

## 2. 桌面布局与所有页面共用的操作规则

### 2.1 布局规格

主验收尺寸：1440×900；兼容验收：1280×800 和 1920×1080。

- 左侧导航固定宽 208px：品牌、学习、成长、工作台；底部帮助/设置。
- 主内容区左右各 32px 留白，最大内容宽 1120px，宽屏居中。
- 页面标题 28–32px；正文 15–16px；辅助文字不小于 13px。
- 页面标题下只保留一句说明；不显示长段产品理念。
- 一级主操作使用一种实心强调色；次操作使用描边或文字。
- 绿色不是所有区域的背景；用中性表面承载内容，把强调色留给当前操作和状态。
- 可沿用当前深色品牌；先建立主次层级，不把换色当成产品重构。
- 活动/材料侧栏宽约 560px；路线审阅和调整采用完整主内容页，避免长报告塞入窄抽屉。
- 弹层出现时只允许一个主弹层获得焦点。内部来源详情使用同一弹层的子视图，带返回，不叠多层抽屉。

### 2.2 共用点击规则

| 编号 | 用户操作 | 统一行为 |
|---|---|---|
| G01 | 点击左侧导航 | 切到对应页面，选中态随之更新；学习路线、活动和材料状态不因导航改变 |
| G02 | 点击 Trellis 品牌 | 回到学习页；存在进行中活动时展示该活动所在位置 |
| G03 | 点击卡片标题 | 打开该对象详情；不隐式开始、完成或采用 |
| G04 | 点击来源链接 | 新标签打开，Trellis 保持原上下文；页面提前标识外部打开 |
| G05 | 点击关闭/按 Esc | 关闭最上层详情；返回到触发它的列表位置，键盘焦点回到触发按钮 |
| G06 | 编辑中关闭详情 | 普通草稿保留并提示“草稿已保存”；不能把草稿写成正式结果 |
| G07 | 点击明确的“放弃草稿” | 有内容时二次确认；确认后仅清除该草稿，保留正式数据 |
| G08 | 点击提交后连续再点 | 按钮显示处理中并禁用；同一提交不得重复创建记录 |
| G09 | 加载失败后点击重试 | 重试失败的操作，保留已输入内容；不清空整个页面 |
| G10 | 点击浏览器后退 | 从详情返回列表，从编辑返回原页；不会撤销已经成功提交的事实 |
| G11 | 刷新或重新打开页面 | 恢复正式路线及已保存进度；本机草稿恢复后明确标识为草稿 |
| G12 | 点击“查看依据” | 展开与当前建议有关的依据；不跳转到独立系统机制页面 |
| G13 | 点击“为什么不能操作” | 就近显示具体阻塞和解决入口，如“先完成前置活动”；不只出现灰按钮 |
| G14 | 点击危险操作确认框的取消 | 回到原位置，不做任何状态修改 |

正式路线的更改必须预览、确认。文字编辑、材料暂存和筛选不逐次弹出确认；不能把“所有 AI 写入需审核”扩展成每一个无风险点击都需要用户批准。

### 2.3 三类状态必须分开

| 对象 | 用户可见状态 | 状态含义 |
|---|---|---|
| 路线覆盖 | 已安排 / 尚未安排 / 暂不学习 | 是否有活动支持当前目标 |
| 活动执行 | 未开始 / 进行中 / 已暂停 / 已完成 | 这次活动做到哪里 |
| 能力证据 | 尚无证据 / 练习中 / 已验证 | 当前证据是否支持能力判断 |

“目标需要它”不等于“已安排”；“活动完成”不等于“能力已验证”。不把这三组状态合成一个进度百分比。

## 3. 学习页 A：第一次进入

### 3.1 默认画面

标题：**你希望学会做什么？**
说明：**描述一个目标，Trellis 帮你选材料、排顺序，并给出这周能开始的第一步。**

内容顺序：

1. 目标输入框，标签“学习目标”。
2. 下方两个示例：“判断一个需求是否适合 AI”“做出一个简单的 AI 应用”。示例是填入文字，不是不可修改的路线类型。
3. 每周可用时间：2 小时 / 3–4 小时 / 5–6 小时 / 自定义。
4. “添加已有材料（可选）”，默认收起；已有材料数量以简短标签显示。
5. 主按钮“查看路线建议”。
6. 补充说明“没有材料也可以开始；建议会说明采用的来源和缺口”。

不展示：空材料表单、尚未分析、领域节点计数、处境编号、能力模型解释。

### 3.2 每次点击

| 编号 | 当前操作 | 界面变化与后续 | 保存与失败行为 |
|---|---|---|---|
| A01 | 点击目标输入框 | 聚焦，可输入或粘贴；显示还可输入字数 | 输入为本机草稿，不自动生成路线 |
| A02 | 点击示例目标 | 目标为空则填入；已有内容则显示“替换当前输入？” | 取消保留原文；不会立刻提交 |
| A03 | 点击时间选项 | 选中对应区间，其他选项取消选中 | 保存草稿 |
| A04 | 点击自定义 | 展示“每周 X 小时”输入，按 0.25 小时递增 | 空值、非正数就近提示；不设置实时计时器 |
| A05 | 点击添加已有材料 | 打开材料添加侧栏，见 M01–M08 | 不丢失目标与时间 |
| A06 | 点击已添加材料名称 | 打开同一材料详情，能看读取状态与内容 | 不重复创建材料 |
| A07 | 点击材料标签的移除 | 只从本次路线输入移除；材料库保留 | 提示“已从本次输入移除”，提供撤销 |
| A08 | 点击查看路线建议 | 校验目标与时间，进入生成状态；无材料允许提交 | 空目标定位到输入框；同一次点击只生成一个请求 |
| A09 | 点击取消生成 | 返回输入页，保留草稿 | 后端已完成但未展示的结果仅作草稿，不自动采用 |
| A10 | 生成失败后点击重试 | 用相同输入重试；保留上次可用结果供返回 | 不重复激活路线 |
| A11 | 点击修改输入 | 返回原输入内容，用户修改后重新请求建议 | 旧结果保留为未采用版本，不影响已有正式路线 |

### 3.3 等待与必要追问

生成中显示“正在整理你的目标和材料”，按钮变为“生成中…”，提供取消。只有真实可确认的处理阶段才显示阶段进度，不编造百分比。

当目标实质影响路线但存在歧义时，最多先问 1–2 个必要问题，例如“你更希望先做出应用，还是先形成产品判断？”选择后继续。不要为了完成一个固定诊断表追问所有用户。

模型不可用：如果已有基线可以满足请求，显示“这次使用已有课程资料生成”，允许查看依据；如果不能满足，说明缺什么并提供返回修改，不生成虚假个性化。

## 4. 学习页 B：路线审阅

### 4.1 默认画面

标题：**这条路线是否适合你？**

顶部摘要显示：
- 目标：用用户能理解的一句话复述，旁边“修改”。
- 假设：例如“按没有开发基础安排”，可以纠正。
- 本周安排：活动数、预计用时，与每周上限分开显示。
- 覆盖情况：能完成哪部分、尚未安排什么、对目标有什么影响。

中间显示三个到五个阶段的简短顺序，每个阶段使用行为结果命名。第一阶段展开，后续折叠。

第一活动预览包括：标题、来源、预计时间、具体起止位置、完成方式。

底部固定操作栏：
- 主按钮：完整方案用“采用路线并开始”；部分方案用“先学习已安排的部分”。
- 次按钮：“调整建议”。
- 链接：“查看材料取舍”。

固定栏不能盖住正文和缺口提示；进入页面的摘要也显示同一个主操作入口，不要求滚到底才能作决定。

### 4.2 点击与状态

| 编号 | 操作 | 点击后的具体变化 | 确认与边界 |
|---|---|---|---|
| B01 | 点击目标旁修改 | 展开目标和时间编辑，保留材料；保存后重新生成草稿 | 不改变正式路线 |
| B02 | 点击纠正基础 | 展开与该假设相关的一项输入，如已有经验 | 生成新建议，旧建议可返回 |
| B03 | 点击阶段标题 | 展开该阶段活动、来源和完成表现 | 只是查看，不切换主路线 |
| B04 | 点击第一活动标题 | 打开活动预览侧栏 | 未采用时主动作是“采用后可开始”，不创建学习记录 |
| B05 | 点击为什么这样安排 | 展开当前选择的 2–3 条具体理由和来源 | 不显示求解器、模型合同等实现说明 |
| B06 | 点击查看材料取舍 | 打开本路线材料面板：当前采用 / 后续 / 不采用 | 每项说清采用哪些章节和原因 |
| B07 | 点击某材料暂不采用 | 面板标记待调整，显示受影响的活动/目标 | 点击“重新生成建议”后才重算草稿 |
| B08 | 点击保留该材料 | 将偏好纳入新草稿，但不保证不适合的材料能覆盖目标 | 无法满足时说明冲突 |
| B09 | 点击撤销本次调整 | 移除该项草稿偏好，回到此次编辑前 | 不重写已确认历史 |
| B10 | 点击调整建议 | 展开目标、投入、材料偏好三个入口 | 修改后先显示新草稿 |
| B11 | 点击采用路线并开始 | 提交确认，成功进入学习页，首个可执行活动展开 | 按钮不同时打开外部课程；用户先看活动范围 |
| B12 | 点击先学习已安排的部分 | 在操作栏再次简述未覆盖结果，用户确认后进入学习页 | 缺口继续标识为尚未安排，不能变成计划中 |
| B13 | 点击暂不采用 | 返回目标输入页，保留输入和建议草稿 | 不删除用户材料 |
| B14 | 确认失败点击重试 | 查询该次确认是否已成功；成功则进入学习页，否则重试 | 防止重复创建正式路线 |

### 4.3 无可执行第一步

若没有任何可靠可执行活动，主按钮不能是“开始”。页面改为：

“目前还不能给出可靠的第一步。”

三个有条件的入口：补充材料 / 缩小目标 / 查看已有范围。选择后回到对应输入位置。不能把一份没有起点的报告包装为可采用路线。

## 5. 学习页 C：正常使用的主界面

### 5.1 首屏结构

标题：**本周学习**。

顶部小条：
“本周目标：判断哪些需求适合 AI”
“已安排 75 分钟 · 每周上限 120 分钟 · 0/2 项完成”
右侧“调整本周投入”。

下面是一份活动列表，不再同时展示任务包、当前片段与另一份连续进度。

```text
本周学习                                      调整本周投入
判断哪些需求适合 AI                  0/2 项 · 已安排 75 分钟

1  理解 AI 能做什么、不能做什么                 45 分钟
   来源：AI for Everyone / What AI Can and Cannot Do
   当前：未开始
   学到哪里：课程中的同名章节
   完成方式：查看活动说明中的具体要求
   [打开课程] [查看说明]                      [这次先不做]

2  了解生成式 AI 的适用范围                     30 分钟
   未开始                                     [查看说明]

[查看完整路线]                               [查看本周已完成]
```

示意文本只表达设计，不把未核实的学习产出当课程事实。

- 优先展开进行中/暂停活动；没有进行中时展开第一个可执行活动。
- 真正存在前置关系才限制开始。推荐顺序不是强制锁定。
- 与当前行动有关的缺口在相关活动旁展示；不阻止本周的路线缺口以一行摘要链接呈现。
- 已完成活动折叠到列表底部，可展开查看；活动 ID 与名称保持稳定。

| 编号 | 操作 | 界面变化 | 状态与异常 |
|---|---|---|---|

| C02 | 点击打开这一节 | 新标签打开已核实章节，原卡片转进行中并显示继续 | 打开链接不等于完成 |
| C03 | 点击打开课程 | 新标签打开课程主页；原卡片继续显示寻找章节的具体指引 | 不伪称章节直达 |
| C04 | 点击继续 | 打开上次保存位置；无更精确位置则使用原入口 | 保留既有反馈和投入记录 |
| C05 | 点击我学完了 | 打开完成反馈，见 F01–F06 | 尚未提交前不推进状态 |
| C06 | 点击我卡住了 | 打开卡点反馈，见 F07–F12 | 活动保持进行中 |
| C07 | 点击先暂停 | 展开可选的停留位置，主操作“保存并暂停” | 成功后标记暂停，不标记失败 |

| C12 | 点击去完成前置 | 定位并展开对应活动 | 不重新生成整周 |
| C13 | 点击查看已完成 | 展开已完成活动，显示完成日期和结果入口 | 不与未完成任务重复计数 |
| C14 | 点击已完成项再次查看 | 打开原活动详情，可重读材料 | 重读不自动撤销完成或降低能力 |
| C15 | 点击查看完整路线 | 进入成长页并定位当前阶段 | 返回学习页恢复列表位置 |

| C18 | 点击最近调整提示 | 查看上次确认的变化及原因 | 只读；撤回需要新的调整提案 |

### 5.3 外部打开失败

浏览器拦截新标签时，提示“课程没有打开”，显示可再次点击的普通链接。保留可重试状态，不能显示“已完成跳转”。

服务端已保存开始，但外部页面未打开时，说明“活动已记录为进行中，课程尚未打开”，允许重试或暂停。不要通过不断重复提交开始操作来重开网页。

## 6. 活动详情 D：围绕一个活动完成所有相关操作

详情顶部：所属阶段 → 活动名 → 执行状态。主区分三个区域：
1. **这次做什么**：步骤、来源、具体位置、预计投入、完成方式。
2. **我的记录**：位置、学习结果、备注、用时。
3. **安排依据**：为什么现在做、与目标关系、来源和限制。

默认展示第一块；其他块按需展开。底部主要动作随状态变化：未开始为打开材料；进行中为记录结果；暂停为继续；已完成为查看结果。

| 编号 | 点击 | 结果 |
|---|---|---|
| D01 | 来源名称 | 打开来源详情子视图，返回仍是该活动 |
| D02 | 外部链接图标 | 新标签打开来源，活动详情不关闭 |
| D03 | 修改学习位置 | 展开章节链接和位置说明；默认带入当前值 |
| D04 | 保存位置 | 校验链接格式，成功显示新位置；只改该用户该活动的位置 |
| D05 | 取消位置编辑 | 返回原位置，未提交草稿可继续保留 |
| D06 | 添加备注 | 展开文本框；保存后出现在我的记录 |
| D07 | 添加已有成果链接 | 输入名称、URL、简短说明；保存为关联证据，默认待验证 |
| D08 | 打开已有成果 | 新标签打开；不改变证据判断 |
| D09 | 查看安排依据 | 展开与本活动相关的简短理由与来源 |
| D10 | 查看前置 | 展示具体前置名称与当前状态；点击可进入相应活动/节点 |

成果链接属于已有产出登记，不在本轮增加文件编辑器或开放作品自动评分平台。

## 7. 反馈 F：每种情境只问必要问题

### 7.1 做完了

标题：**这次完成了吗？**
默认显示当前活动的明确完成说明。可选填写一句结果和实际用时；不默认虚填 30 分钟。用户没有记录用时就保留未知。

| 编号 | 点击 | 结果与状态 |
|---|---|---|
| F01 | 我学完了 | 展开完成说明、可选结果与用时；主按钮“记录完成” |
| F02 | 添加结果 | 展开文字或已有成果链接输入，不强制变成考试 |
| F03 | 记录完成 | 保存完成事件；能力仍按已有证据判断，不自动升级 |
| F04 | 保存成功 | 同一区域显示“已记录完成”，下面提供下一可执行活动 |
| F05 | 继续下一项 | 关闭反馈，定位下一活动；由用户点击打开材料 |
| F06 | 撤销这次完成 | 在结果页提供短期撤销入口；有后续依赖记录时说明影响后确认，不删除证据历史 |

### 7.2 卡住了

标题：**你卡在哪里？**
提供三项：“内容看不懂”“操作做不出来”“找不到材料”，以及一句可自由描述的补充。

| 编号 | 点击 | 结果与状态 |
|---|---|---|
| F07 | 内容看不懂 | 追问具体概念或段落；不显示完成状态选择 |
| F08 | 操作做不出来 | 追问进行到哪一步、预期与实际结果；允许粘贴错误文字 |
| F09 | 找不到材料 | 显示当前定位指引、原入口与补充位置入口 |
| F10 | 获取下一步建议 | 保存卡点并生成简短帮助；等待时保留原活动 |
| F11 | 采用补前置/缩小范围建议 | 展示对本周的具体影响；确认后更新相关安排 |
| F12 | 暂不调整，继续原活动 | 保存卡点记录，保持原安排；关闭后可继续 |

没有可靠帮助时明确说明不能判断，给出补信息或查看原课程支持入口，不用通用鼓励文案冒充解决方案。

### 7.3 今天先到这里 / 时间不足

| 编号 | 点击 | 结果与状态 |
|---|---|---|
| F13 | 今天先到这里 | 显示可选停留位置，主按钮“保存并暂停” |
| F14 | 保存并暂停 | 活动标为暂停，下次默认展开该活动；不影响能力状态 |
| F15 | 本周时间变少了 | 进入时间调整，显示当前投入和建议变化 |
| F16 | 保持原计划 | 仅记录暂停，未完成项保留；不会以超期标红惩罚用户 |

### 7.4 检查理解

| 编号 | 点击 | 结果与状态 |
|---|---|---|
| F17 | 检查理解 | 展示当前活动匹配的检查说明、预计投入与题目 |
| F18 | 选择答案/输入回答 | 只更新本机草稿；不立即显示掌握升级 |
| F19 | 提交检查 | 保存结果，展示依据、解释和未验证边界 |
| F20 | 查看为什么 | 展开评分或判定依据；不只显示一个分数 |
| F21 | 再试一次 | 显示可重试题目；保留前次记录，不覆盖历史 |
| F22 | 返回活动 | 回到当前活动，显示继续、补强或完成记录入口 |
| F23 | 登记课程原测验结果 | 标识为“用户登记的外部测验结果”，可补链接；不当作系统独立验证 |

## 8. 工作台 M：材料列表、添加、理解与采用

## 10. 路线与本周调整 R

所有修改入口复用同一个“调整预览”，避免每个页面各自创建确认机制。

### 10.1 调整本周投入

| 编号 | 点击 | 结果 |
|---|---|---|
| R01 | 调整本周投入 | 显示当前每周上限、本周已完成用时（未知则标未知）、剩余安排 |
| R02 | 选择新投入 | 更新草稿，不立即移动任务 |
| R03 | 看看如何调整 | 显示保留、暂缓、新增活动，以及为什么 |
| R04 | 确认本周调整 | 仅更新本周承诺；已完成记录保留，长期目标不自动变化 |
| R05 | 取消 | 回到原页与原计划，草稿可保留供继续 |

### 10.2 统一调整预览

布局：左侧当前方案，右侧建议变化；顶部一句原因；底部确认/保持原方案。小改动用明确的差异列表，不强制两栏长报告。

必须区分：
- 新增什么；
- 删除或暂缓什么；
- 顺序和投入怎样变；
- 哪些学习记录保留；
- 有没有新缺口；
- 影响本周还是长期路线。

| 编号 | 点击 | 结果 |
|---|---|---|
| R06 | 某条变化 | 展开对应活动和理由 |
| R07 | 查看完整建议 | 打开新路线草稿；可返回差异预览 |
| R08 | 修改这次建议 | 返回发起该提案的输入，如材料取舍或每周时间 |
| R09 | 确认调整 | 原子保存新版本并切换；出现“已更新”及查看变化入口 |
| R10 | 保持原方案 | 拒绝本次提案，回原页；新材料与原学习记录均保留 |
| R11 | 确认期间状态已变化 | 提示“你的学习进度有更新”，读取最新差异供重审，不盲目覆盖 |

新材料进入库不自动打断本周；普通完成不重新规划整周。

## 12. 具体文案与内容生成标准

### 12.1 名称映射

| 系统内部说法 | 前台说法 |
|---|---|
| 处境 / 学习目标假设 | 你的目标 / 当前按这些情况安排 |
| 任务契约 | 活动说明 |
| 来源分诊 | 材料用途 |
| 学习信号 | 你的回答 / 学习记录 / 检查结果，按事实使用 |
| 出口检查 | 检查理解 |
| 能力节点 | 具体能力名称；详情里才解释结构 |
| 物化调整 | 已调整 / 建议调整 |
| 选课范围 | 本路线会考虑的材料 |

### 12.2 每个活动必须产出合格内容

必须具备：动作标题、来源、可定位范围、预计投入、具体行为、完成说明、相关依据和实际前置。

不合格：
“能在真实场景中判断何时需要问题定义与用户价值。”

合格的设计示例：
“选一个你熟悉的需求，写明是谁在什么情境下遇到什么困难，再说明用 AI 是否比普通规则更合适。”

合格与否不能只靠字段不为空。材料没有支持到相应深度时，应改变活动或说明边界，不编造学习收益。学习者的记录不自动成为正式能力验证。

### 12.3 时间与数量

时间以 15 分钟为最小单位；复杂活动拆为连续活动。每周通常 2–4 项核心、0–2 项可选，以实际预算和活动质量为准，不为凑数生成任务。每周上限与已安排时长分开显示，保留弹性，不让未填满预算看起来像错误。

## 14. 桌面优先的开发顺序与交付包

不能把全部页面交给实现者自由拼接。按以下顺序，每个包都有明确入口、结果和验收对象。

| 顺序 | 交付包 | 覆盖点击 | 完成后用户能做什么 | 必须通过 |
|---|---|---|---|---|
| 1 | 桌面学习活动主流程 | C、D、F 的完成/暂停 | 已有路线用户能开始、返回、完成和继续 | 同一活动只有一份主操作；外部打开与恢复一致 |
| 2 | 首次设置与采用 | A、B | 新用户从目标进入第一项活动 | 无材料可走通；缺口不伪装成已安排 |
| 3 | 卡点与检查 | F 其余分支 | 不同学习困难得到不同处理 | 回答保留，检查失败不算答错 |
| 4 | 材料到路线 | M、R 的材料分支 | 添加材料并看到其如何影响路线 | 不重复材料，不经过多次含糊确认 |
| 5 | 路线、调整与跨周 | P、R、W | 看长期方向、调整投入并进入下周 | 所有页面状态一致，原记录保留 |
| 6 | 桌面视觉与恢复收口 | G 与全部桌面状态 | 长内容、错误、空白和中断都能正常使用 | 1440×900、1280×800、1920×1080 实测 |
| 7 | 手机专项适配 | 桌面已稳定的上述流程 | 手机可以顺畅完成同一任务 | 在桌面主流程验收之后开始 |

基础状态一致性与来源边界在对应交付包内完成，不等到最后“视觉收口”才处理。手机不是第 1–6 包的阻塞项，但桌面改动不能让现有手机入口完全无法操作。

本报告不预估虚假的开发天数；实现者需先核对现有接口能否支持各点击，再给出工作量。前端重组可复用已有存储、版本与课程分析能力；新增数据库对象必须有具体不足证据，不能为了设计术语先扩架构。

## 15. 逐流程桌面验收样例

以下均为本版产品验收要求，不是已经测得的结果。

### 场景一：零材料新手

A01 填目标 → A03 选 2 小时 → A08 生成 → B03 看第一阶段 → B11/B12 采用 → C02/C03 打开材料 → F01 记录完成 → F05 定位下一项。

验收：用户无需知道内部术语；全部正式状态可恢复；材料主页与章节直达明确区分。

### 场景二：已经收藏很多材料

M01 添加 → M04 保存读取 → M14 查看读取范围 → M22 看用途 → M23 看章节 → M24/R09 确认调整 → C01 在本周找到对应活动。

验收：同一材料始终可找回；一次最终确认表达采用决定；原完成记录保留。

### 场景三：材料不足

A08 → B 显示未覆盖结果 → B12 采用部分 → C17 看缺口 → P04 查看同一未安排目标 → 补材料 → R09 确认更新。

验收：未安排目标不能在成长页成为已安排；系统给出实际选择而非只有警告。

### 场景四：学习中断

C04 继续 → C07/F13 暂停 → F14 保存位置 → 关闭页面 → 重新进入 → C04 恢复原位置。

验收：未完成不被改成完成；暂停不代表能力下降。

### 场景五：没有学会

F07 或 F08 → F10 获取建议 → F11 预览补强 → R09 采用 → C 找到对应帮助或活动。

验收：卡点处理不要求先填写完成状态；拒绝建议可继续原路线。

### 场景六：投入变化与下周

C16/R01 改时间 → R03 看变化 → R04 确认 → W01 复盘 → W03 下周草稿 → W06 采用 → W08 查历史。

验收：跨周和调整不丢历史；不自动创建固定日程。

### 场景七：请求失败

生成失败重试、确认响应丢失、材料读取失败、反馈提交失败、调整前进度变化分别执行对应恢复操作。

验收：输入不丢、不重复创建、失败不冒充成功；恢复后仍位于同一对象。

## 16. 交给实现者时必须附带的材料

1. 本报告的点击编号与页面状态。
2. 同一个真实长度样例贯穿的桌面页面稿，包含空、等待、成功、部分可用和失败。
3. 每个操作复用的现有接口与需要补齐的最小行为。
4. 状态对照：覆盖、活动、能力分别从何处读取。
5. 每个交付包的真实浏览器截图与上述流程执行记录。

当前报告已明确下一版交互行为；还不能把它当成已开发或已验收。设计建议待审阅，手机滞后的优先级已按用户本轮要求记录。
