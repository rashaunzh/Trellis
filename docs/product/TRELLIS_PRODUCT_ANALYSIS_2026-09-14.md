### 0.2 我认可的产品方向

Trellis 应帮助缺少学习规划经验的人，把目标与可用材料转成有依据、能开始的学习活动，并在中断、困难和约束变化后继续推进。它的价值需要同时体现在首次选择和后续恢复；不能把生成路线数量作为产品成功。

当前最需要解决的是：用户理解、行动与正式状态之间缺少统一表达。解决方式是一个活动列表、一套活动详情、一套反馈与变更规则，而不是继续增加首页模块。

| 决策 | 为什么 | 代价与边界 |
|---|---|---|
| D01 首期围绕一条当前路线完成闭环 | 减少新手在多目标间切换和系统维护成本 | 历史路线可读；并行路线管理延期 |
| D02 保留零材料与少量材料两种入口 | 尚无证据支持排除其中一类；两者都是契约覆盖的情况 | 零材料只依赖有依据的已发布资源，不能补造课程内容 |
| D03 学习以一份周活动列表为主 | 让开始、暂停、完成与恢复指向同一对象 | 详细规划理由进入路线审阅或活动详情 |
| D04 完成记录与能力证据分开 | 避免把行动数量包装成能力认证 | 成长页面可能显得保守，但更可信 |
| D05 重要变更审阅后生效，普通记录直接保存 | 将摩擦放在有实际后果的地方 | 需要实现版本冲突与响应丢失恢复 |
| D06 首个开发包完成桌面活动闭环 | 用户能独立完成一个任务，比多个半成品模块更可验收 | 不先重建完整课程、知识图谱或手机导航 |
| D07 AI 负责候选理解与解释，规则负责正式状态边界 | 输出不稳定性不能转成计划和数据不稳定性 | 模型不可用时降低建议能力，如实说明限制 |
| D08 低负担收集必要记录 | 用户没有义务替系统维护大量字段 | 信息不足时少作判断，不靠默认值补假数据 |

## 1. 从真实问题推导产品价值

### 1.1 问题不是“缺少一张学习路线”

用户可能面临四种不同困难：

1. **选择困难**：不清楚目标要求什么、材料是否合适、该从哪里开始。
2. **行动困难**：路线看起来合理，但一次学习的入口、范围和结束条件不明确。
3. **恢复困难**：中断之后忘记位置、理由与下一步，需要重新整理上下文。
4. **判断困难**：不知道一次完成说明了什么，也不知道困难是否需要改变计划。

Trellis 是否值得存在，取决于减少这些困难的收益能否超过录入、审阅、记录和维护的成本。上述困难的发生频率与严重程度需要实测，不写成“每天发生”或“全程只生成三次路线”。

### 1.2 首次价值与持续价值分别成立

首次价值：用户能够更快做出一个有理由的学习选择，知道第一步以及尚未解决的缺口。即使只使用一次，也可能有价值。

持续价值：用户下次回来时能恢复；系统把已发生的学习与新约束转成可审阅的下一步，而不是重复生成一份互不相干的计划。

因此两个阶段都要评价：第一次是否值得开始，以及后续是否值得回来。首次价值不能依赖用户先持续使用数周。

### 1.3 替代方案和差异化假设

以下是机制比较，不是已完成的用户竞品测试；其他工具能力随配置而异。

| 用户现有办法 | 可能的优势 | Trellis 需要证明的增量价值 | 新增负担 |
|---|---|---|---|
| 跟随一门课程 | 顺序已给定，进入简单 | 识别目标不匹配、前置缺口和适合裁剪的部分 | 引入另一处状态和学习说明 |
| 与通用 AI 对话 | 入口灵活，容易追问 | 目标、来源、正式计划、记录与版本持续一致 | 用户需要审阅候选并理解变更 |
| 任务工具加笔记 | 用户控制强、记录自由 | 降低自行拆解活动与关联学习依据的成本 | 需要理解活动与材料之间关系 |
| 请有经验者指导 | 判断有情境、能及时纠错 | 在可支持范围内提供及时且可追溯的辅助 | AI 判断可能错误，需显式限制 |
| 完全自行探索 | 无额外工具维护 | 帮助减少不确定性和重复选择 | 目标与材料输入成本 |

不承诺“所有人都需要 Trellis”。若用户只需沿课程原顺序学习，且无恢复或调整困难，应允许低干预模式：少量活动、简单记录，不强迫全面材料审阅。

### 1.4 产品承诺与非目标

承诺：告诉用户当前建议、采用依据、可执行入口、完成记录方式和未解决问题；正式计划可追溯，用户可以拒绝调整。

不承诺：保证学会、保证求职结果、自动证明全部能力、读取未授权课程全文、替代完整教学平台。

本阶段不新增通用聊天首页、每日任务体系、打卡、实时计时器、排行榜、多领域平台、自动开放作品评分、复杂并行目标、手机专项。保留现有小屏基本可访问性。

## 2. 首要用户与研究假设

### 2.1 先选行为情境，不虚构人口画像

首要用户候选：有一个大致 AI 学习目标，缺少选材和安排经验，希望借助外部课程开始学习，并且需要在中断后接续的人。材料可以没有，也可以只有一两份；不要求专业术语、固定每日时间或高频反馈意愿。

| 差异 | 产品应如何适应 | 为什么 |
|---|---|---|
| 目标模糊 / 明确 | 模糊时给可编辑解释与最多一个关键澄清；明确时直接保留原意 | 不用一轮长问卷惩罚所有用户 |
| 无材料 / 少量材料 | 基线资源起步 / 带材料生成候选 | 不把材料整理变成使用前提 |
| 零基础 / 有相邻经验 | 提示必要前置；允许用户修正或选择可选检查 | 自报经验不是已经完成诊断 |
| 时间稳定 / 波动 | 周预算可调整；未完成活动可保留和重新安排 | 时间变化不应导致整条路线推倒重来 |
| 初次 / 恢复使用 | 初次给起点；恢复优先上次活动与位置 | 同一个首页不应对两类人展示相同的大报告 |

多材料专业整理者、企业课程管理者、职业方向咨询、多目标重度项目管理暂不作为优化中心。此取舍是聚焦实验，不宣称这些用户没有需求。

### 2.2 假设、验证与失败后的动作

| 编号 | 待验证假设 | 需要的证据 | 若不成立 |
|---|---|---|---|
| H01 来源与范围说明能帮助新手信任第一步 | 首次操作后能复述依据与缺口；比自行处理减少犹豫 | 精简理由或改变默认资源，不继续加解释字段 |
| H02 无材料用户也能获得可执行起点 | 无材料样例有真实可打开资源，用户能开始 | 收窄支持目标并清楚提示，避免空泛路线 |
| H03 周预算比逐日安排更合适 | 连续使用中用户能调整预算并恢复，无反复“计划失败” | 保留区间约束，减少预算对入口的阻断；不自动引入日历 |
| H04 最少反馈足以支持有价值的继续建议 | 完成、暂停、卡点三种记录后的建议被理解和使用 | 只在影响判断时追问，不把所有表单加长 |
| H05 统一活动入口能减少迷失 | 原界面与原型任务对照：错入口、解释次数、完成率 | 调整信息层级，而不是只替换视觉样式 |
| H06 用户愿意持续保留学习状态 | 2–4 周内实际恢复与调整案例 | 调查价值不足还是维护过重，保留单次规划价值 |
| H07 用户愿意为持续辅助付出成本 | 价值验证后访谈与真实付费试验 | 不提前建立复杂计费或强制付费模型入口 |

## 3. 用户任务和产品成功标准

| 任务 | 进入时的问题 | 完成后必须知道或得到什么 | 产品不得强求 |
|---|---|---|---|
| J01 确定起点 | 我从哪里学起 | 第一项活动、理由、来源与未覆盖部分 | 完整职业规划、全部材料目录 |
| J02 审阅路线 | 这是否符合我的目标和时间 | 当前采用范围与正式确认的后果 | 理解模型或工作流术语 |
| J03 开始或继续 | 这次具体做什么 | 入口、范围、上次位置、结束条件 | 再读完整路线报告 |
| J04 保存结果 | 我完成了/先停下了 | 记录已保存，下一次如何继续 | 虚填用时、每次做测验 |
| J05 处理困难 | 不懂/不会做/资源不可用 | 一步可尝试的帮助或明确限制 | 不断重试模型直到成功 |
| J06 修改安排 | 时间或目标变了 | 变更前后、影响活动、确认与放弃路径 | 牺牲已经完成的记录 |
| J07 理解进展 | 我到底获得了什么 | 计划覆盖、执行、能力证据分别可解释 | 接受一个无依据的总分 |

拟定任务成功标准是开发验收目标，不是目前已达到的结果。优先观察独立完成、错误理解、失败恢复和信息负担；点击少不自动等于体验好。

| F07 | [决策规则](../../lib/learning/intelligence/decision-kernel.ts)对 quiz_report 明示未独立验证，confidence=0.5；有效情景判断为 0.85 | 不能声称两类信号完全未区分 | 保留区别，检查后续状态与展示是否压平 |
| F08 | [服务](../../lib/learning/intelligence/service.ts)为自报设置 assessmentKind=self_report；知识状态又按推进结果写较粗的等级 | 来源类型与概括状态不是一回事 | 不将“已有记录”显示成同强度能力结论 |
| F09 | 服务包含 submissionId/hash 去重与 expectedSignalId 冲突校验 | 幂等与乐观锁分别存在 | 分别测试重复请求和旧版本提交 |
| F10 | 学习页 confirm 在请求后 refresh，异常进入错误提示 | 响应丢失后的确定性恢复尚需验证 | 用原提案查询结果，不重新生成路线 |
| F11 | 工作台有读取范围、版本、片段审阅和采用入口 | 已有可信来源管理基础，操作关系仍需简化 | 合并用户意图，不删除底层确认边界 |
| F12 | 决策规则对卡点有确定性分支 | 不能断言帮助完全依赖模型 | 区分基础处理、可选 AI 解释和正式变更 |
| F13 | [草稿模式](../../lib/learning/intelligence/feedback-draft.ts)actualMinutes 是必需数字 | 去掉界面默认值不能单独完成空值设计 | 切片包含草稿兼容与未知值传播 |
| F14 | startCurrent 先写开始状态再尝试打开外部页面 | 尝试打开不等于外部页面加载或用户学习 | 记录用户开始意图；展示备用链接与真实状态说明 |

不以“数据层优于多数产品”作评价：本轮没有跨产品架构比较。现有底座值得复用，但其聚合语义与页面表达仍有具体缺口。

## 6. 学习机制：从目标到证据

### 6.1 必须解释的因果关系

目标需要什么能力 → 目前知道哪些基础 → 哪些材料支持这些内容 → 为什么先做这个活动 → 记录说明了什么 → 下一步为什么保持或改变。

每一步允许“不知道”。用户自报不是起点诊断，课程目录不是全文读取，打开链接不是学完，完成活动不是能力验证。一道情景题仅支持其覆盖的有限表现。

### 6.2 四种信息、三类用户进展

| 信息 | 例子（合成样例） | 合法结论 |
|---|---|---|
| 目标范围 | 想设计一个有依据的 AI 问答功能 | 尚不表示路线已覆盖 |
| 计划覆盖 | 已安排来源辨别活动，尚未安排实际系统评测 | 可以说明安排与缺口 |
| 活动执行 | 用户记录完成一次阅读比较 | 可以继续，不推出能力掌握 |
| 能力证据 | 对一个给定案例作出有解释的判断 | 只说明该案例、条件和评价标准下的表现 |

前台将目标范围作为参照，分开展示计划、执行与证据三类进展。不得合成“总体掌握度 80%”。只有统计定义清楚时显示“已完成 1/3 项活动”；不把时间填满当作达标。

### 6.3 活动的最低质量门

每项活动至少有：可理解的动作、与目标的关系、来源或明确的无来源限制、学习范围、预计投入、结束条件、结果记录方式、遇到困难的入口。

预计时间以 15 分钟递增，标注为估计；不强制把预算全部排满。材料无法准确定位时展示“课程主页，需要手动找到……”，不得伪造章节链接。

缺少可执行来源的候选不应进入正式学习活动：可以成为“补充材料”动作，或明确停在有限路线审阅；不能让用户点击一个注定无效的“开始学习”。

## 7. 对象、状态与写入规则

### 7.1 对象职责

| 对象 | 负责保存什么 | 不代表什么 |
|---|---|---|
| 目标 | 用户确认的方向、解释和现实约束 | 已完成诊断 |
| 路线版本 | 阶段、顺序、材料取舍与覆盖缺口 | 本周全部要完成 |
| 阶段 | 一个结果范围及退出条件 | 一周、课程或项目 |
| 周安排 | 区间内选定活动与预算 | 每日课表 |
| 活动 | 可执行动作、范围、来源引用、执行状态 | 一项能力认证 |
| 材料版本 | 原始输入、实际读取范围、分析与审阅 | 已被当前路线采用 |
| 学习记录 | 用户报告、位置、可选用时、具体回答 | 自动可靠的能力结论 |
| 证据 | 来源、条件、评价标准与支持范围 | 通用能力总分 |
| 调整提案 | 变更前后、原因、受影响对象和基准版本 | 已生效计划 |

这些是产品语义，不要求逐个新增数据表。优先复用现有对象；D1 继续保存正式业务状态，工作流快照不能替代它。

### 7.2 关键状态转换

| 对象 | 转换 | 触发与保护 |
|---|---|---|
| 路线 | 草稿 → 正式 | 展示具体范围后用户采用；同一请求重复返回同一结果 |
| 路线 | 正式 → 历史版本 | 新版本确认时切换；保留旧完成记录和引用 |
| 活动 | 未开始 → 进行中 | 用户明确开始；仅打开详情不改变状态 |
| 活动 | 进行中 → 暂停 → 进行中 | 保存/恢复位置；不自动推导为时间不足 |
| 活动 | 进行中或暂停 → 已完成 | 用户报告完成或明确的完成规则；不自动升级能力 |
| 活动 | 已完成 → 更正后继续 | 用户明确更正，历史记录保留；若影响后续检查，展示影响 |
| 材料 | 已保存 → 处理中 → 待审阅 / 分析受限 | 分析版本绑定来源，失败不删除原输入 |
| 材料 | 已审阅 → 可供路线选择 | 接受用户选定片段；尚未改变任何正式路线 |
| 提案 | 待审阅 → 已采用 / 已放弃 / 已过期 | 基准版本改变则过期；重新计算后再确认 |
| 证据 | 新记录 → 待评价 / 有限支持 / 不足以判断 | 明确来源与条件；重要正式能力变化单独审阅 |

完成更正、材料归档、跨设备恢复等可能需要接口补齐，属于待实施能力，不声称现有后端全部支持。

### 7.3 什么操作需要确认

- 切换筛选、展开说明、选择活动：不确认，不写正式状态。
- 保存笔记、暂停、用户报告完成：按钮表达清楚即可保存，提供更正；不额外弹“确定吗”。
- 编辑草稿偏好：仅改草稿；点击“更新方案”才计算新候选。
- 采用路线、调整正式周安排、改变重要能力结论：先展示具体影响再确认。
- 移除未提交的材料行：直接移除并允许撤销。
- 归档已经保存的材料：说明是否仍被活动引用；不静默删除历史来源。
- 永久删除用户数据：展示范围与不可恢复部分并明确确认；不是本次页面清理顺带执行的动作。

确认摩擦取决于后果与可恢复性，不取决于按钮是否调用 AI。


## 8. 桌面信息架构与一致性规则

### 8.1 三个入口为什么保留

学习对应“做什么与继续”；成长对应“方向、记录与证据”；工作台对应“材料与辅助内容”。三类任务可以共享对象但不共享整块页面。保留现有导航有迁移成本优势，仍需用新手测试验证名称理解；暂不增加第四入口。

| 页面 | 默认内容 | 次级入口 | 不在首页展开 |
|---|---|---|---|
| 学习 | 当前路线名、周预算摘要、一份活动列表 | 查看路线、调整安排、历史周 | 路线取舍计数、完整推导、重复时间线 |
| 成长 | 路线阶段、未覆盖目标、完成记录与证据入口 | 能力详情、成果链接、历史版本 | 无关领域总节点数、暗示综合掌握度的分数 |
| 工作台 | 材料列表、添加入口、处理状态筛选 | 材料详情、附加记录与辅助链接 | 无操作的“测试机”“陈列室”、空设置区 |

成长页可以显示当前活动名称作为指向同一详情的链接；这种摘要是导航，不再提供另一套独立操作和状态。

### 8.2 学习页结构示意（非像素稿）

    左侧导航 | 路线名称                  查看路线 · 调整安排
             | 本周预算 120 分钟 · 安排 90 分钟 · 尚有目标未覆盖
             | ------------------------------------------------
             | [继续上次] 活动 A   进行中   预计 30 分钟
             |            上次位置：用户保存的位置或“尚未记录”
             | 活动 B             未开始   预计 30 分钟
             | 活动 C             未开始   预计 30 分钟
             | 已完成（折叠）     查看历史周

点击活动行后，桌面右侧打开同一活动详情，列表保留选中态。**不再在列表上方增加独立“当前活动大卡”。** 窄桌面可将详情占据主内容区，并保留返回列表与选中位置。详情内容过长时内部滚动，底部主操作可见但不遮挡文本。

建议下一步只是对现有列表项的标记。用户可以检查其他活动；若有真实前置约束，详情说明“可预览，完成 X 后建议开始”，只有确需阻断的规则才禁用操作并说明原因。

### 8.3 全局操作约定

| 编号 | 操作 | 必须发生的行为 |
|---|---|---|
| UX01 | 导航到其他页面 | 已保存状态不变；保留合理的筛选与滚动；未保存编辑按 UX04 处理 |
| UX02 | 从任意入口打开活动 | 同一活动 ID、相同详情；返回到来源页面与原位置 |
| UX03 | Esc、关闭、返回 | 关闭当前子视图后再关闭详情；焦点回到触发按钮，不穿透操作背景 |
| UX04 | 离开有未提交输入的视图 | 可保存草稿则明确“已保存于此浏览器”；否则提供继续编辑/放弃；不能静默丢失 |
| UX05 | 提交时再次点击 | 禁用重复动作并显示保存中；服务端对同一提交去重 |
| UX06 | 保存响应丢失 | 显示“正在核对保存结果”，查询原请求；结果未知时不显示成功或要求重新生成 |
| UX07 | 读取旧版本后提交 | 保留输入并展示版本已变化；读取差异后决定重试，不能覆盖另一设备 |
| UX08 | 打开新设备 | 恢复账号内正式状态；本机草稿不冒充已同步；说明草稿仅在原浏览器 |
| UX09 | 页面无数据 | 说明缺什么和一个可执行入口，不渲染假统计或假路线 |
| UX10 | 出错 | 错误紧邻相关动作，说明保存是否发生、能做什么；全局提示仅辅助 |
| UX11 | 控件禁用 | 就近说明条件；不能仅靠悬停或颜色 |
| UX12 | 删除或更正 | 根据第 7.3 节的影响提供撤销、版本更正或确认，不一律加弹窗 |
| UX13 | 链接访问 | 不把请求发出、页面获得焦点或返回页面当作学习完成 |
| UX14 | 长处理 | 显示真实可知状态；没有阶段信号时写“正在处理”，禁止假进度条 |
| UX15 | 无权限或登录失效 | 保护本地输入，明确需要重新登录；不退回其他 owner 数据 |

正式服务器草稿跨设备同步属于独立功能，优先级低于正式状态恢复；需要另行定义草稿冲突，不通过悄悄上传个人本地文件实现。

## 9. 从首次进入到确认路线

### 9.1 页面组织与输入选择

第一页只问“你希望能做什么”，提供少量合成示例作为可编辑起点；不替用户默认选择职业或长期路线。第二步确认基础与每周时间，材料作为可跳过区域。两步以内是本轮建议，原因是减少一个长表单的视觉负担，同时让用户核对关键约束；若测试证明单页更清楚，可调整布局而不改变语义。

每周时间可提供 30/60/120/240 分钟快捷项和“自定义”；自定义正数按 15 分钟递增，不自动选择。快捷值是交互建议，不是人群统计。基础提供“刚开始/接触过/不确定”和可选补充；标注为用户自述，不称为诊断。

来源允许 URL 或文本，标题可后填。不能要求新手为每门课程手动复制完整目录。只提供主页时，候选范围必须受限。

### 9.2 操作规格

| 编号 | 用户动作 | 页面响应与数据变化 | 错误、取消与验收 |
|---|---|---|---|
| IN01 | 点击示例目标 | 填入可编辑示例；若有输入先询问替换，或插入为建议 | 不把示例写入正式用户偏好 |
| IN02 | 输入目标并继续 | 检查非空、显示实际合同允许的长度；保留原文 | 不凭字数短就否定合法目标 |
| IN03 | 目标过宽 | 给一句解释和最多一个影响路线的澄清问题，可改写或保留有限范围 | 不启动无限问答；没有足够信息时明确限制 |
| IN04 | 选择基础和时间 | 显示“本周可调整”，所有值可返回修改 | 不把“不确定基础”当零基础事实 |
| IN05 | 展开添加材料 | 一行 URL/文本入口，可增加来源，选填标题 | 关闭折叠不清空输入 |
| IN06 | 从材料库选择 | 选择可用版本并带入引用，展示读取/审阅状态 | 不复制第二份材料；未分析材料仍标未分析 |
| IN07 | 移除草稿来源 | 从本次输入移除，给撤销；不删除材料库原件 | 有已保存分析时仍可重新选回 |
| IN08 | 点击生成方案 | 展示将使用的目标、时间与来源范围；创建可追踪请求 | 防重复；输入快照绑定结果 |
| IN09 | 处理中离开或取消 | 保留输入；若后台可恢复则返回查询；不支持时明确取消本次等待 | 取消客户端请求不冒充服务器已取消 |
| IN10 | 部分材料失败 | 展示成功与失败来源，允许重试失败项或用现有依据继续 | 不把失败来源计入已分析 |
| IN11 | 模型不可用 | 有可靠基线时提供“查看基线方案”；陌生材料仅保存/规则候选 | 不称为个性化分析成功；不要求付费才能记录活动 |
| IN12 | 再次进入 | 恢复已保存的候选或本地输入草稿，标注保存范围 | 新设备仅显示服务端已有内容，不虚构本地草稿 |

### 9.3 路线审阅页面

顺序：目标解释与约束 → 已安排/未安排内容 → 第一项活动预览 → 本周活动与总预计时间 → 后续阶段 → 材料取舍 → 可展开依据。采用按钮固定但不遮内容。

完整与有限方案都可审阅。只有有可执行起点且缺口已明确时，有限方案才可采用；空方案不能通过“有限”标签绕过可执行性检查。

| 编号 | 用户动作 | 行为与正式状态边界 |
|---|---|---|
| RV01 | 查看缺口 | 逐项说明尚未安排内容及影响，提供补材料/修改目标入口 |
| RV02 | 预览第一项活动 | 打开候选详情，可看来源；候选外链标“预览”，不创建学习进度 |
| RV03 | 将材料改为暂缓/不采用 | 只更新草稿偏好，页面显示“有未计算的修改” |
| RV04 | 点击更新方案 | 一次提交偏好，生成新候选；旧候选保留可查看，新旧差异可对照 |
| RV05 | 修改输入 | 回填目标、时间、材料；来源版本未变时复用分析，不无故清空 |
| RV06 | 有未计算修改时采用 | 要求先更新或放弃这些修改；不能采用看似包含修改的旧结果 |
| RV07 | 采用方案 | 显示即将建立的路线、首周活动和时间；确认原提案与版本 |
| RV08 | 确认结果未知 | 查询同一提案；已成功则进入活动列表，未成功才重试原确认 |
| RV09 | 已有正式路线又有草稿 | 明确“继续现有路线”“查看调整草稿”“放弃草稿”三个不同动作 |
| RV10 | 放弃草稿 | 未编辑时直接放弃并可返回正式路线；有未保存输入按 UX04 处理 |
| RV11 | 候选依据更新或版本冲突 | 提示过期，重新生成差异；不能继续用旧摘要确认新数据 |

不要求用户确认每段 AI 解释；确认的是将成为正式安排的具体内容。

## 10. 开始、返回、完成与暂停：第一交付包

### 10.1 活动详情的内容顺序

1. 标题、执行状态、预计时间。
2. 本次要做什么、做到哪里停止。
3. 主要来源：准确位置或“仅课程主页”；上次保存的位置优先。
4. 主操作“开始学习”或“继续学习”。
5. 返回后的“记录完成”“先暂停”“需要帮助”。
6. 可展开的为什么现在做、判断依据、补充材料和记录历史。

同一时刻按状态强调一个主操作。已完成详情强调查看记录或下一项；仍可打开材料复习，但不重复创建完成记录。

### 10.2 开始与外部返回

| 编号 | 操作 | 必须发生的行为 |
|---|---|---|
| AC01 | 点击活动行 | 仅选择与展示详情；不标记进行中 |
| AC02 | 点击开始学习 | 记录用户开始意图；尝试打开来源新标签；详情显示“已开始记录，外部阅读进度需你返回后登记” |
| AC03 | 外链未打开或被拦截 | 原页面始终保留普通链接和复制链接；允许重试打开；不宣称已检测外部页面成功 |
| AC04 | 仅有课程主页 | 按钮写“打开课程主页”，旁边显示需手动寻找的范围；可保存实际位置 |
| AC05 | 没有可用来源 | 提供补位置、查看其他已核验来源或回到方案；不显示无效开始动作 |
| AC06 | 用户切回 Trellis | 保留同一详情与上次状态；不根据焦点或耗时自动完成 |
| AC07 | 返回列表 | 保持活动选中和滚动位置，列表状态与详情一致 |
| AC08 | 选择其他可开始活动 | 展示对应详情；不自动完成或暂停原活动，也不静默调整排序 |
| AC09 | 查看有前置活动 | 显示前置理由和入口；确需阻断时解释条件，不提供失效按钮 |
| AC10 | 刷新/新设备继续 | 从正式活动与位置恢复；若之前保存结果未知先核对，不创建第二条活动 |

“已开始”表达用户意图，不证明外部网站加载，更不证明用户已学习。实现不能依赖 window.open 返回值准确识别所有浏览器拦截；备用链接是必要设计。

### 10.3 完成与更正

| 编号 | 操作 | 写入与结果 | 失败/更正 |
|---|---|---|---|
| AC11 | 点击记录完成 | 打开轻量记录视图，明确“记录本次已完成，不验证能力”；附言和实际用时选填 | 不展示全部理解/测验字段 |
| AC12 | 保存完成记录 | 写用户报告、可选附言/用时，活动完成；显示下一项入口 | 不等待可选 AI 解释才保存成功 |
| AC13 | 用时留空 | 保存未知，汇总显示记录覆盖情况 | 不能变成 0 或预计时间，不能默认 30 |
| AC14 | 选择实际用时 | 正数按 15 分钟递增；表明是近似记录 | 不限制必须等于预计；不在未输入时计算效率 |
| AC15 | 点击下一项 | 打开下一项详情；仍需明确开始才改变状态 | 不自动跳出外部课程 |
| AC16 | 误点完成后更正 | 从结果或历史选择“更正记录”，展示影响，保存更正版本 | 若后续已开始，不级联删除后续记录；呈现可能需回看的关系 |
| AC17 | 重复保存/网络重试 | 同一提交标识对应同一结果；成功后清理草稿 | 有较新记录时保留输入并说明冲突 |

此处“轻量记录视图”选择两步而非瞬间完成，是为了在当前证据语义混乱时让用户知道保存的含义。若用户测试显示长期重复说明负担大，可缩成明确的一键“记录完成”加可选编辑；必须保留同样的语义与恢复能力。

历史记录中的 30 分钟可能是真实填写，也可能来自旧默认值；不能批量判为虚假或清零。迁移仅对有可验证来源的记录修正，无法区分时保留原值并说明历史采集限制。新记录的未知值必须贯穿输入、草稿版本、服务校验、保存和统计；导入旧草稿时不可把既有数字误当作新用户再次确认。

### 10.4 暂停与位置

| 编号 | 操作 | 行为与验收 |
|---|---|---|
| AC18 | 点击先暂停 | 展示已有位置，可选修改；位置未知时明确未知，不强制输入理由 |
| AC19 | 只填写页码/时间戳说明 | 允许保存说明并保留原来源 URL；无新 URL 不应阻止记录位置 |
| AC20 | 保存暂停 | 保存位置和暂停状态；不推断时间不足，不改变正式路线 |
| AC21 | 取消暂停 | 返回当前详情，活动状态不变；编辑按草稿规则处理 |
| AC22 | 下次点击继续 | 展示上次位置与记录，打开现有来源；不能保证外部视频自动跳到时间戳 |
| AC23 | 修改来源链接 | 校验链接与活动归属，只更新此活动的个人定位；保留修改历史，不覆盖共享课程 |
| AC24 | 来源登录/付费/失效 | 说明访问要求，允许记录障碍、选择有依据替代或提交调整；不绕过访问限制 |

## 11. 反馈、检查与 AI 帮助

### 11.1 按意图提问，而不是四套独立数据

完成、暂停、困难、检查共享同一活动、记录历史和状态服务。界面拆分意图不等于建立四份互不一致的反馈系统。

| 入口 | 必须问 | 可选内容 | 保存后默认结果 |
|---|---|---|---|
| 记录完成 | 不额外询问理解程度 | 附言、用时 | 用户报告完成，可继续 |
| 先暂停 | 不必填写理由 | 已有位置的修正、备注 | 保持未完成，可恢复 |
| 需要帮助 | 困难类型或一句描述至少一种 | 具体问题、引用片段 | 记录问题并给建议，不自动替换路线 |
| 做一次检查 | 对当前问题作答 | 解释、是否使用帮助 | 有限检查结果，不自动认证整个能力 |
| 登记课程测验 | 通过/未通过 | 外部成绩或题目链接 | 明示自报，保留来源差异 |

### 11.2 逐次操作

| 编号 | 操作 | 系统与页面行为 |
|---|---|---|
| FB01 | 点击需要帮助 | 提供“不理解内容/不知道怎么做/资源打不开/其他”；展示当前活动，不重复问目标 |
| FB02 | 选择困难类型 | 只显示相关一个必要追问：概念或片段、卡在哪一步、访问问题；允许“不确定” |
| FB03 | 保存问题 | 先可靠保存记录；若后续帮助失败仍能看到原问题，活动保持未完成 |
| FB04 | 请求解释或建议 | 使用此活动、已读材料及用户输入；说明引用范围，推断标“建议” |
| FB05 | 信息不足 | 明确缺少的内容，提供补充片段/查看原课程/暂存后继续，不循环追问 |
| FB06 | 模型失败 | 保留问题，展示确定性可行路径：回看现有范围、保存位置、稍后重试；不伪造定制帮助 |
| FB07 | 查看建议 | 显示建议动作、原因、依据、是否改变计划；解释性建议可直接阅读 |
| FB08 | 建议会替换、插入或移动活动 | 转到调整预览；用户确认后才改变正式安排 |
| FB09 | 点击建议无帮助 | 保留原记录，可指出原因或结束；不默认重复付费调用 |
| FB10 | 点击做一次检查 | 展示目的、覆盖范围、是否计入证据；题目与版本绑定 |
| FB11 | 提交答案 | 防重复；显示判断依据和局限。先呈现结果，用户可继续或选择回看 |
| FB12 | 检查不可用 | 允许只记录完成或问题；不能强迫使用一个失效检查才能继续 |
| FB13 | 登记课程测试通过 | 明示“你登记的结果，未独立读取或核验”；不升级为独立验证 |
| FB14 | 结果与自我感觉冲突 | 同时保留。例如题目通过但用户不确定，可回看；不抹去矛盾记录 |
| FB15 | 关闭或刷新反馈视图 | 草稿恢复并显示保存范围；提交成功后删除对应草稿，旧草稿遇新记录提示冲突 |
| FB16 | 查看上次反馈 | 打开历史原记录和当时建议；标注哪些已采用，哪些只是建议 |

### 11.3 证据展示规则

证据不只显示强弱颜色。最少列出：来自用户自报、具体答题还是外部评价；发生时间；涉及哪个活动与能力；使用帮助与否；支持什么、不能支持什么。

当前 self_report 标记应保留。需要修复的是从详细信号到概括状态再到 UI 的语义损失，不能仅增加同样的标签。重要能力状态变更应有明确证据集合与审阅入口；没有可靠评价方案时只显示记录，不显示“已验证”。

## 12. 材料、成长、路线调整与跨周

### 12.1 材料管理

默认显示“我的材料”和添加入口。筛选为全部、待处理、可供路线选择、已用于路线、已归档；同一材料可同时有分析状态和使用关系，不能硬塞成一个互斥标签。归档隐藏常规列表，历史活动仍保留来源；永久删除另行处理。

| 编号 | 操作 | 行为与理由 |
|---|---|---|
| MT01 | 添加链接或文本 | 可只保存，不强求类型或分析；展示能读取的范围 |
| MT02 | 保存重复来源 | 显示已有材料，允许打开或更新；不能静默覆盖新版内容 |
| MT03 | 搜索/筛选 | 按名称与状态找材料；无结果可清除筛选，不显示“没有材料”误导 |
| MT04 | 点击读取并分析 | 创建版本化结果；保留原文，显示成功、受限或失败 |
| MT05 | 查看分析 | 显示实际读取范围、可用片段、引用与限制；目录不可写成全文 |
| MT06 | 选择片段 | 可多选；无依据关联不能默认全选，需明确待核验原因 |
| MT07 | 点击保存选择并用于后续选材 | 一次表达审阅与候选采用意图；底层各步骤需可恢复，不提前宣称全部成功 |
| MT08 | 候选采用部分失败 | 显示已保存选择和未完成步骤；重试失败步骤，不让用户重复逐片段确认 |
| MT09 | 用于新路线/调整当前路线 | 带材料引用进入输入或变更草稿；已有正式路线不因跳转改变 |
| MT10 | 修改材料并保存 | 展示版本变化和旧候选失效范围；正式路线维持旧引用直到采用调整 |
| MT11 | 重新分析 | 新建分析版本，不覆盖历史引用；只重试本材料 |
| MT12 | 从学习详情添加参考 | 加入同一材料库并关联该活动，显示“参考材料，不替换主来源” |
| MT13 | 移除活动参考关联 | 只解除此活动关联，材料库内容保留 |
| MT14 | 归档材料 | 明示仍被哪些路线/活动使用，隐藏于默认列表但历史可查 |
| MT15 | 查看笔记/工具链接 | 作为辅助内容呈现真实操作，不把类型名称映射成虚假课程身份 |
| MT16 | 完全删除材料 | 单独说明活动引用、分析、缓存的处理范围；没有完整删除能力就不显示永久删除承诺 |

保留来源透明度，合并的是用户操作，不删除服务端的审阅与版本保护。批量并行分析不是首包要求：先让一份材料的保存、失败、重试与采用可靠。

### 12.2 成长与成果

默认按当前路线解释进展：阶段与方向 → 已安排与未安排 → 完成记录 → 可查看证据。不同维度使用独立标签，不画一条从“计划中”自然升级到“已验证”的进度梯子。

| 编号 | 操作 | 行为与边界 |
|---|---|---|
| GR01 | 打开成长 | 显示当前路线与阶段；没有路线时说明缺少什么，并给建立路线入口 |
| GR02 | 点击阶段 | 展示阶段目标、活动与退出条件；找不到阶段时说明待定位，不默认第一阶段 |
| GR03 | 点击活动 | 打开与学习页相同详情，可返回原位置；不创造第二份执行状态 |
| GR04 | 查看目标缺口 | 按实际材料/活动映射显示未安排；目标集合本身不证明覆盖 |

| GR10 | 查看历史路线/记录 | 只读其原版本，明确非当前；如需采用须新建调整草稿 |

首期成果仅做已有活动的链接或短文本记录，不扩展为作品集平台与开放式自动评分。若暂不能形成完整保存/查看/更正链，隐藏成果编辑入口，不能用空卡片充数。

## 13. AI 产品机制、质量与成本

### 13.1 AI 的统一产品约定

每个 AI 输出必须关联输入快照、来源版本和结果标识；用户能够知道它是候选、已保存记录还是正式采用结果。说明采用依据不等于展示模型内部思维过程，前台只展示可核验来源、约束和简洁理由。

| AI 场景 | 输入 | 输出必须包含 | 明确禁止 | 不可用时 |
|---|---|---|---|---|
| 目标理解 | 用户原文、基础自述、预算 | 可编辑解释、关键歧义、支持范围 | 把推测基础写成已诊断 | 保留原文，让用户选有限范围 |
| 材料分析 | 实际取得文本与来源信息 | 读取范围、片段引用、能力关联候选、限制 | 只凭标题声称读完全文 | 保存材料；标为规则拆分或未分析 |
| 路线候选 | 目标、已核验资源、前置约束、材料偏好 | 阶段、活动、来源、理由、覆盖缺口、估计 | 无来源章节、虚构能力掌握、自动正式写入 | 有支持范围时显示基线方案，否则说明缺口 |
| 活动帮助 | 当前活动、用户困难、允许读取的材料 | 具体一步、依据/推断区分、适用条件 | 将外部材料指令视为系统命令 | 确定性恢复路径与保留问题 |
| 调整建议 | 原路线版本、反馈、已完成记录、新约束 | 变更清单、影响与原因、未改变内容 | 静默删除历史或重排正式活动 | 允许修改草稿与继续原活动 |
| 结果总结 | 实际记录及其类型 | 来源、支持范围、冲突与不确定性 | 完成数量等于能力、单题证明全面掌握 | 展示原始记录和规则说明 |

### 13.2 哪些必须由确定规则控制

权限、来源访问边界、输入校验、版本、重复提交、正式写入、已完成记录保留、时间粒度、活动归属、确认前后状态都不能由模型临时决定。

模型生成候选之后，至少检查：引用是否存在、来源是否实际读取、活动是否可执行、前置是否有支持、是否超出用户约束、是否把未知写成确定事实。校验失败应返回可解释的有限结果或拒绝该候选，不通过润色掩盖错误。

规则回退不等于模型输出。用户应看见“基于已发布资料生成”或“尚未完成语义分析”，而不是后台换路由后前台仍宣称完成同等个性化处理。

### 13.3 延迟与成本如何成为产品约束

本轮未运行成本或真实模型基准，不填写当前价格、成功率与 p95 延迟。下一包模型验收必须记录：

- 每个有效用户任务的调用数、重试数、token 与实际账单成本。
- 用户等待分布，区分抓取、模型、校验、保存；不只看一次最快响应。
- 候选被采用、修改、放弃的比例及具体原因。
- 模型不可用时基本流程的任务完成情况。

成本计算口径：一次被接受的有效结果的全部调用成本，包含失败和重试；不能用单次请求价格代表完整用户成本。预算由实际模型、样例结果和维护资源确定，不在无数据时编造商业毛利。

减少无价值调用的顺序：复用未变化来源分析 → 合并草稿偏好后一次生成 → 只重试失败来源 → 限制无依据的自动循环 → 再比较不同模型。保存完成、暂停和查看记录不应要求付费模型。

### 13.4 AI 评价用例

| 用例 | 必须检查的结果 |
|---|---|
| 模糊目标 | 允许纠正解释，不强行生成精确承诺 |
| 无材料 | 仅使用真实支持范围；不伪造私人课程内容 |
| 仅主页 | 明示定位限制；不输出假章节直达 |
| 相互重复材料 | 说明重叠与取舍，不为了展示覆盖全都采用 |
| 目标与基础冲突 | 前置有理由；自述与诊断区分 |
| 时间不足 | 缩小安排或显示超出，不靠虚假时间估计达标 |
| 来源内恶意指令 | 不影响权限、确认和系统行为 |
| 课程内容变化 | 新候选绑定新版本，不改写历史引用 |
| 自报通过但感觉不懂 | 保留两种记录，不自动确认能力 |
| 模型断开或输出结构错误 | 状态可恢复，限制真实，基本记录可用 |
| 调整期间新增学习记录 | 旧提案失效，避免覆盖新进展 |
| 检查题过泛 | 标为反思或不支持判断，不借题目形式伪造评价效力 |

质量评价分别看依据真实性、目标相关、前置合理、可执行性、约束符合、表达可理解、确认正确和恢复能力。涉及伪造来源、未确认正式写入、跨用户信息时一项失败即阻止该版本交付；其他质量项记录具体失败，不用综合高分抵消严重错误。

## 14. 同一合成样例贯穿完整流程

本节是设计验收夹具，不是用户真实资料、真实课程结论或已发生的测试结果。材料中的标题与片段均为合成，只有正式验收替换为有来源的内容后才允许宣称课程准确性。

样例输入：希望能为一个内部知识问答工具写清需求与基本评价方法；刚开始学习 AI；每周 120 分钟；有一份合成材料，只有课程主页与目录，目录包含“任务定义、回答依据、失败案例”。首周候选三项各预计 30 分钟，总 90 分钟；这只是样例时间，不推导通用缓冲比例。

| 步骤 | 用户看见与操作 | 状态及验收重点 |
|---|---|---|
| 1 | 输入目标与 120 分钟，保留基础自述 | 不显示已诊断，不要求职业简历 |
| 2 | 添加材料主页和目录 | 显示仅目录可见；不声称已读课程正文 |
| 3 | 查看候选：定义使用问题、辨别依据、记录失败案例 | 第一项有范围与结束条件；未安排实际系统评测明确列为缺口 |
| 4 | 采用有限路线 | 采用按钮不把缺口消失；首周 90 分钟明确显示 |
| 5 | 点击第一活动 | 同一详情显示“打开课程主页，手动找到任务定义” |
| 6 | 点击开始并切回 | 活动进行中；外链打开尝试不等于完成 |
| 7 | 暂停，填“目录第一节，已写两类问题” | 只保存位置和记录，不推断能力或时间不足 |
| 8 | 刷新后继续 | 恢复同一活动、原位置与主来源 |
| 9 | 记录完成，用时留空 | 已完成一项；实际用时未知；没有已验证能力 |
| 10 | 第二项遇到不理解，保存问题 | 问题保留，活动不完成；帮助可失败但记录不能丢 |
| 11 | 建议补充前置活动 | 仅显示提案；原三项正式安排不变 |
| 12 | 查看影响并采用 | 新版本说明插入内容、预计时间与是否移到下周 |
| 13 | 成长页看记录 | 分别看到安排、完成、未验证；可返回同一活动 |
| 14 | 准备下周 | 具体列出未完成迁移与新增，用户确认才生效 |

该样例必须再运行三个变体：完全无材料；只有可直接进入的章节；确认时断网且另一设备提交了新记录。通过主路径不能替代这三个变体。

## 15. 功能取舍与旧实现迁移

### 15.1 保留、重组、补齐与延期

| 能力 | 决定 | 原因与实施限制 |
|---|---|---|
| 路线版本、服务端确认、D1 状态 | 保留 | 已有业务边界，不因页面重排重建底座 |
| 反馈去重、冲突检测、草稿恢复 | 保留并验收 | 防丢失与多设备协作必需；未知用时需补兼容 |
| 来源范围、引用、分析版本 | 保留 | 是可信方案基础 |
| 任务包、当前卡、时间线 | 重组为一个执行列表和一套详情 | 保留契约信息与历史，不保留三套操作入口 |
| 反馈综合表单 | 按意图重组 | 服务与历史统一，不复制四套数据 |
| 材料片段确认与采用 | 合并用户入口，保留底层确认和恢复 | 避免相似按钮串联，同时确保结果真实 |
| 分支按钮与无操作卡片 | 降为静态或移除其入口 | 有完整动作才重新提供按钮；不因此删除相关历史数据 |
| 成长全领域视图 | 降为二级 | 当前路线与证据优先 |
| 成果编辑 | 最小引用闭环后再开放 | 暂不建设作品集与开放评分平台 |
| 批量并行材料分析 | 延期 | 一份材料处理可靠后，再用实际量级决定 |
| 完整诊断、课程平台、手机专项 | 延期 | 超出第一闭环；小屏现有可访问性继续保留 |

“移除界面”不等于删除数据表或接口。迁移前核查活动 ID、来源引用、草稿版本和旧记录展示；不能因为新设计不显示旧字段就抹去用户历史。

### 15.2 与既有桌面规格的衔接

本文使用独立操作编号，避免与既有 A/B/C 等编号混淆；数量不是完成率。

| 本文范围 | 既有规格范围 | 本文明确补充或修正 |

| UX | 全局 G | 多设备正式状态与本机草稿区分、响应未知查询 |
| IN/RV | 首次输入与路线审阅 A/B | 时间快捷项只是建议；未计算偏好不能混入确认 |
| AC | 学习与活动 C/D | 不再增加独立当前大卡；开始意图与外链加载分开 |

实施每个包之前，将本文选定行为更新进既有桌面规格的对应段落，在同一提交消除冲突，再开发该包。本文负责产品理由与验收逻辑，桌面规格负责确定的界面行为；不得让两个互相冲突的版本同时作为实现标准。涉及正式契约边界变化时明确提出，而不是静默写入。

## 16. 开发顺序、依赖与验收门

不按页面数量报进度，不给没有团队与运行基线的工期承诺。每包完成一个用户可执行结果；若发现后端缺口，在同包修复最小范围，不先做无关重构。

| 包 | 交付结果 | 必要工作 | 依赖 | 通过门 |
|---|---|---|---|---|
| P0 桌面活动闭环 | 开始、外部返回、记录、暂停、恢复 | AC、相关 UX；未知用时全链路；同一列表与详情；保留现有活动内容 | 当前正式路线与活动 | 第 14 节步骤 5–9及失败恢复，无假用时/假能力 |
| P1 首次价值与路线信任 | 无/少材料用户能审阅并开始 | IN/RV；基线与有限路线表达；确认结果查询 | P0 可作为确认后落点 | 无材料、仅主页、部分失败、确认断网均可解释恢复 |
| P2 困难处理与材料 | 记录问题、获得有限帮助、材料可采用 | FB/MT；引用、版本与可恢复操作 | P0/P1 的活动与候选机制 | 帮助失败不丢记录，材料变更不静默改变路线 |

## 17. 评价计划：工程、体验、AI 与用户价值分开

### 17.1 可复现验收矩阵

| 场景 | 操作 | 必须观察到 |
|---|---|---|
| 正常开始 | 列表进入详情，开始外部课程 | 同一活动状态，真实链接类型，返回入口 |
| 弹窗被拦截 | 点击开始后外链未打开 | 可直接打开/复制的备用链接，无假完成 |
| 空用时 | 完成但不填用时 | 记录未知，汇总不填 0/30/预计值 |
| 暂停恢复 | 只记录文字位置，刷新 | 位置保留，原链接不丢，状态未完成 |
| 记录断网 | 保存后响应丢失 | 查询原提交，恢复唯一结果 |
| 两设备编辑 | 旧反馈或旧提案提交 | 冲突明确，原输入可取回，新状态不被覆盖 |
| 无材料 | 生成支持范围内方案 | 有真实起点与缺口；不支持时诚实停止 |
| 来源受限 | 只有主页或抓取失败 | 限制可见，可选择继续有限方案或补充 |
| 低风险草稿修改 | 切换材料偏好 | 不立即替换候选或正式路线，显式更新后计算 |
| 模型失败 | 请求分析或帮助 | 输入和记录保留，基本操作继续 |
| 信号矛盾 | 自报通过但不确定 | 两种事实保留，不强制显示掌握 |
| 正式调整 | 审阅新增/移除活动后确认 | 仅确认内容生效，完成记录保留 |
| 成长跳转 | 从能力记录打开活动 | 同一详情、同一数据、可回来源 |
| 键盘与长内容 | Tab/Esc/缩放/长材料 | 焦点合理、按钮可达、内容不遮挡 |

桌面建议检查 1440×900、1280×800、1920×1080 和 200% 缩放；这些是本项目测试尺寸，不是证明用户设备分布。手机专项后置，但修改不得造成现有小屏入口完全不可用。

### 17.2 新手可用性研究

建议先招募 6–8 名符合首要情境的参与者，覆盖无材料、少量材料和中断回归；这是形成性研究样本，不代表统计显著性或市场规模。参与者使用测试数据，避免为了研究上传隐私材料。

任务：自行建立或理解路线、开始指定活动、暂停、恢复、记录完成、处理一个卡点、解释成长记录、审阅调整。主持人先不解释页面，不问“你喜欢吗”替代任务观察。

记录：是否独立完成、误点与回退、请求解释次数、关键误解、放弃位置、用户复述“这个确认会改变什么”。任务后再问哪里费力、是否值得在原工具之外维护这些记录。

拟定第一轮门槛：严重状态或隐私错误为 0；若两人出现同一关键理解错误，必须修改并复测；其余以具体任务成功记录判断，不用小样本百分比夸大效果。该门槛是内部验收决策，并非研究界通用标准。

### 17.3 长期使用验证

桌面闭环通过后，进行 2–4 周试用，关注实际恢复与调整事件，而非强制每天登录。允许用户没有学习安排，区分无需求、外部已学未记录、功能失败、忘记使用和价值不足。

记录用户是否能够利用上次位置继续、是否采用建议、为什么放弃、维护记录是否比收益更费力。实际学习效果需要独立前后任务或成果评价，不能以连续登录和活动完成数代替。

### 17.4 指标定义与解释边界

| 指标 | 口径 | 不应误读为 |
|---|---|---|
| 首次有效起步 | 新测试用户理解并进入有依据的第一活动；排除演示账号 | 注册数或生成成功率 |
| 恢复成功 | 有未完成活动的返回会话中，用户找到原活动并继续 | 所有访问都应学习 |
| 记录可靠性 | 有效提交中出现丢失、重复、错误归属的次数 | 页面 toast 显示成功 |
| 反馈负担 | 记录所需字段、任务时间、放弃与解释原因 | 点击越少越好 |
| 方案可采用性 | 候选中经审阅被采用的比例，分无材料/有材料 | 被采用即正确或学会 |
| 来源准确性 | 抽检引用可追溯、范围声明真实的比例 | 链接能打开就内容正确 |
| 有效帮助 | 问题被记录后用户能尝试下一步及其反馈 | AI 输出长度 |
| 学习表现 | 独立任务在明确标准下的变化及局限 | 活动完成数、用时总量 |

建议埋点事件：candidate_requested/viewed/adopted、activity_viewed/start_requested、external_link_requested、record_saved、resume_requested、help_failed、revision_viewed/adopted/conflicted。external_link_requested 只能证明请求打开；不得命名为 course_consumed。事件默认只含匿名化标识、版本、状态和错误类别，不把原始学习文本发送到分析服务。

没有运行数据前不设置宣称已达成的留存、转化或收入目标。先建立可解释基线，再决定改进幅度。

## 18. 运营、隐私与商业可持续性

### 18.1 最小运营能力

用户遇到错误时能提供结果 ID、时间和问题类型；支持人员据此定位版本与阶段，无需要求用户公开全部学习材料。错误分为访问、来源、模型、校验、保存和版本冲突，避免所有失败显示“AI 出错”。

外部课程变化时标记受影响来源，形成新的分析与调整候选；历史记录保留原引用和采集范围。不要后台更新材料后让用户原来的活动悄悄改变。

### 18.2 数据与跨设备

正式路线、活动与记录由账号对应的业务存储恢复；本机 localStorage 草稿明确说明范围。Git 仓库同步代码和交付文档，不同步用户学习数据库、个人偏好文件或模型密钥。

向外部模型发送材料之前，说明实际发送范围与用途；不默认发送全部历史、无关笔记或其他用户信息。外部内容只能作为待分析数据，不能授予工具权限或改变确认边界。

永久删除与导出要分别定义对象、历史引用、模型供应商侧数据和缓存范围。尚未实现完整能力时，不能用一个“删除成功”承诺超出实际范围；需要相应运营说明与实现任务。本文不是法律合规结论。

### 18.3 商业判断

目前优先验证个人使用价值与服务成本，不建议先搭建复杂订阅、额度和模型商店。可能的长期付费价值是假设：多次可靠调整、节约选材时间、连续状态与有依据的学习辅助。

免费或低成本基本流程继续满足现有契约；不让用户为保存记录、恢复活动或查看已有路线被迫购买模型。收费试验应在有效任务价值明确后进行，按实际成本、支持负担和付费意愿确定，本文不编造市场规模与收入预测。

- 文档写完就称产品更新完成。

- 自动测试通过就称新手体验通过。
- 本地截图就称线上身份与状态验收。
- 用户登记完成就称学习效果已证明。
