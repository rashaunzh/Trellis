## 1. 对前稿的修正

用户指出八周AI样本的核心活动与常见课程结构不同、措辞不够专业，要求调研实际产品机制并细化交付目标。前稿的问题不只是名词：它把完成AI产品案例的项目步骤当作课程路线，遗漏了学习目标、知识范围、示范、练习、形成性评价与前置检查之间的对应关系。

项目式学习可以保留，但项目应作为应用与综合评价的载体，不能用“问题定义→原型→评测→复盘”代替所有教学。非编程学习者仍需要必要的技术概念；免编程不等于免技术理解。AI通识、AI产品管理和AI应用开发必须分别定义结果与先修要求。

本文件取代前稿第5节样本作为后续课程设计依据的地位；前稿样本仅保留为历史项目练习骨架。其状态明确为未完成课程设计，不继续据此编排正式学习路线。

## 3. 应当分开的四层功能

1. 课程蓝图：要学习的概念和技能、先后关系、教学活动、评价。它给出内容范围，不能临时用项目动词代替。
2. 个性化路径：根据目标与起点，选必修、免修待验证、补充和选修单元，并说明取舍。
3. 周期学习计划：把已选单元放进8／12周，核算学习、练习、评价、修订和复习时间。
4. 自适应调整：根据新证据修改后续活动、难度、材料或节奏；改变目标、先修结构或正式路线需明确审阅确认。

课程章节、知识模块、能力阶段、周次不能互相替代。一个模块可能跨周；一周可以学习新内容并复习旧内容；一个项目可以贯穿多个模块。

## 4. Trellis路线引擎的实现规格提案

### 4.1 内容准备

建立首个领域的课程蓝图和版本化学习单元目录。每个单元包含：学习目标、知识点、必要前置、可用教学资源、示范案例、练习、形成性评价、补救、延迟复习、投入范围与出处。模型可起草，但需内容审查和来源核验后才进入正式目录。

陌生材料可作为待审核候选进入：识别结构与读取范围→映射现有目标→标出重复、补充、缺失和无法确认内容→形成使用提案。不得把一个新链接直接升级为可信课程，更不能只按标题完成覆盖判断。

无需先做全领域大图；先建设一个有教学与评价闭环的领域范围。没有可信领域包时，可保存目标、协助探索并提供明确标注的草案，不宣称已支持该领域的可靠路线。

### 4.2 用户输入与起点

收集目标方向、可观察终点、周期／期限、分周投入、单次时段、材料和访问限制。诊断通过相关题目、任务或既有成果建立起点；记录是否自报、是否限时、是否使用帮助、评价版本、时间及适用范围。

AI方向不能只问“有没有编程基础”；还需检查与目标相关的概念理解和任务表现。雅思需区分考试类型、目标总分和单项、近期分项样本。起点未覆盖项保持未知，可生成含诊断活动的暂定计划，不自动免修。

### 4.3 生成与校验

目标版本 + 起点证据 + 学习单元目录 + 时间／材料约束 → 目标覆盖表 → 路径候选 → 周安排候选 → 质量检查 → 可审阅提案。

硬约束：必达目标有教学和评价覆盖；必要前置已满足或已安排；来源和任务真实可用；每周总投入不超预算；截止日期不被改写；未验证知识不能默认为已掌握。

软偏好：优先已有材料、减少重复、少切平台、照顾语言和练习偏好。不能为了少用课程而牺牲核心目标。规划顺序为先满足硬约束，再优化偏好，不用未经验证的加权分数遮掩缺口。

模型负责语义映射、差距解释与候选组合；程序负责预算、依赖、引用、版本和字段约束；内容评价负责教学目标与实际活动是否对齐。不能只让同一模型自评一句“路线合理”就放行。

8周切12周必须区分“降低周负荷”和“增加练习深度”；由目标约束决定，不默认扩范围。规划可容纳只说明投入和顺序不冲突，不等于能预测学会或提分。

### 4.4 三种调整

活动内调整：学习者请求解释、示例或再练一次，在已说明的练习范围内响应，保存帮助条件。

周安排调整：根据错误类型、速度或现实投入改变练习／复习配比，展示被替换活动和时间变化，用户采用后更新正式周任务。

路径调整：免修、补前置、换材料、延长期限、改变目标范围。展示目标覆盖和阶段影响；确认后产生新版本，既有答案、成果和评价保留。

错误一次不重排整课；成绩波动先检查任务可比性。需要帮助才能完成、独立完成、隔一段时间仍能完成，属于不同证据。早期采用透明规则，不伪造掌握概率；是否引入知识追踪模型，须以数据量、任务类型和验证结果决定。

## 5. 专业化学习单元示例：从课程到操作

示例单元：**分类模型评估：混淆矩阵、Precision与Recall**。适用于AI产品管理技术基础分支，不是所有AI通识学习者的必修；在路径中安排前必须判断目标需要。

以下题目和阈值是Trellis拟定规格，不是Duke原题，也不是已验证评价工具。相关教学主题依据Duke的[Evaluating & Interpreting Models模块](https://www.coursera.org/learn/machine-learning-foundations-for-product-managers)。公开大纲确认了相关教学主题；课程内练习题与个人访问权限尚未核验。

| 字段 | 交付内容 |
|---|---|
| 先修要求 | 理解二分类、真实标签和模型预测，能解释比例；未满足者先做对应补学 |
| 学习目标1 | 给定标注与预测，正确区分TP、FP、FN、TN |
| 学习目标2 | 从混淆矩阵计算并解释Precision、Recall |
| 学习目标3 | 给定误报与漏报的业务后果，为评价指标选择提供有依据的解释 |
| 教学资源 | 对应课程的分类误差指标讲解；保存课程与章节标题、入口和访问条件，不虚构视频深链 |
| 示范 | 一份带完整解题说明的分类案例，解释每种错误及指标含义；具体案例需正式内容编制 |
| 引导练习 | 对案例填写四类结果，允许查看逐步提示；提示使用记录随尝试保存 |
| 独立检查 | 新案例独立作答；计算、解释和业务选择分别评价，不能只看总分 |
| 补救 | 类别混淆回到判别练习；计算错回到公式与计数；计算对但业务解释错进入错误成本案例 |
| 复习 | 后续检查使用另一情境，检验是否保留与迁移；间隔先作为透明配置再用数据校准 |
| 估计投入 | 在讲解、练习、独立检查、反馈修订分项编制后得出范围，当前不填未经核验的总时长 |

可直接用于规格审阅的独立检查样题：100条消息中，预测为垃圾的40条里30条确为垃圾；预测为正常的60条里10条实际为垃圾。要求填写TP／FP／FN／TN，计算Precision和Recall，并分别解释“丢失重要邮件”和“垃圾邮件进入收件箱”对应的错误。

参考解：TP30、FP10、FN10、TN50；Precision=30/40=0.75，Recall=30/40=0.75。业务题不能仅因算出数值就通过，应能将误报、漏报和具体成本联系起来；不能据单题推断整个模型评估领域已掌握。若要求讨论阈值变化，还必须增加相关教学与题目，不能临时加考。

| 点击状态 | 必须呈现和保存 |
|---|---|
| 点「查看本单元」 | 目标、先修、讲解与练习范围；主按钮「开始学习」，依据按需展开 |
| 点「打开讲解」 | 已核验入口与章节定位说明；记录已开始，不标已掌握 |
| 点「开始练习」 | 展示实际案例与可操作答题区，提供「查看提示」；草稿可恢复 |
| 点「提交答案」 | 保存答案、题目版本、提示条件与尝试；等待评价失败时保留提交 |
| 点「查看反馈」 | 按计算、解释、应用分别显示判断与答案引用；每个缺口有补救入口 |
| 点「针对这项再练」 | 打开与错误对应的新练习；不能返回泛化“继续努力” |
| 点「完成独立检查」 | 给出本单元检查结论及未覆盖范围；需要改变路线时显示提案 |

对照雅思：Task 2段落论证训练也要有目标、示范、练习、评价和修订，但不能照搬上述客观判题规则；口语发音需可评价音频条件。通用平台统一生命周期，领域包负责教学与评价。

首轮C5参考矩阵建议：2个范围（AI产品管理、IELTS Academic）×2个周期（8／12周）×3种起点（未知、基础薄弱、部分已有证据）共12组。数量是覆盖设计，不是有效性保证。雅思用于合同验证，正式开放需相应领域包通过检查。

另覆盖8种异常：目标超预算、关键材料不可访问、用户排除必需来源、考试日期提前、停学一周、重复同类错误、评价争议、旧提案遇到新反馈。每种都需要一份输入→实际输出→期望行为对照，不能只写测试名。

质量集应划分开发与未见保留样例；使用保留样例修复后重新补集。教学内容专家审查、模型自动评分和真人观察分别记录，不能由同一模型的自评替代全部验证。

## 7. 用户最终应收到的路线成果包

一次路线生成成功，界面必须交付：

1. 目标与假设摘要：终点、起点依据、周期、时间、未解决问题。
2. 课程路线图：学习模块、前置、必修／免修待验证／选修，附选择理由。
3. 逐周计划：各周学习目标、单元、投入、检查和复习；远期可调整标识明确。
4. 材料清单：确切来源、用到的部分、访问方式、替代和暂不用材料的原因。
5. 当前学习单元：可点开的教学内容、练习、提交与反馈，而非任务标题。
6. 评价与调整说明：怎样判断进展、什么情况下补学／跳过／延期、修改前后如何查看。

“生成成功”不能只代表JSON解析成功：至少要通过目标覆盖、前置、资源可用、容量和首项可执行检查。更广泛的教学合理性与学习效果仍需相应评估，不能由静态检查自动宣告。
