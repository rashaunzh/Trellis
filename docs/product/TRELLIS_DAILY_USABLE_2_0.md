# Trellis 日用 2.0 功能状态

更新日期：2026-08-29

## 当前目标

Trellis 日用 2.0 的目标是从“作品级 Agentic Learning Companion 可展示”推进到“用户本人可以连续几周真实使用”。判断标准不是页面数量，而是学习循环是否能稳定闭合：计划、活动、材料、证据、评审、修订、周复盘、下周编排和作品迭代都要能落到持久状态。

## 已落地功能

- `/api/learning/workspace?weekKey=YYYY-Www` 可读取指定周；不传时保持默认当前周。
- `workspace.weeklyPlanHistory` 汇总已生成周、当前/未来标记、活动数、完成数、accepted evidence 数和复盘状态。
- `/learn` 顶部展示计划历史，用户可以切换到已生成的周计划，不覆盖其他周证据、活动或作品记录。
- `learning_week_reviews` 支持周复盘归档；同周可主动更新，系统不会静默改写已归档复盘。
- `/api/learning/week-review` 支持即时复盘、归档复盘、基于复盘生成下一周计划。
- 用户资源进入工作台收集箱后，可映射到节点，并自动进入当前与后续同节点活动的 `inputRefs`。
- 活动抽屉同时展示系统资源和用户资源，保留资源用途、内容片段和来源链接。
- Evidence Review 保持规则版可运行；短证据会退回，修订后 accepted 才能推动掌握确认。
- 作品区展示作品版本链、最近裁决、缺失 rubric 和下一步；系统状态面板已折叠为工程/质量信息。

## 2026-08-29 产品重心调整

本轮确认 Trellis 的日用 MVP 不应继续优先堆“课程推荐”或“作品集包装”，而要把学习型 AI 产品的核心定位落到：

1. 判断内容是否专业、是否适合当前阶段；
2. 从多份课程/材料中切出本周真正值得看的片段；
3. 把课程片段转成低启动成本行动；
4. 用轻量判断记录、情景选择和小产出观察理解；
5. 将通过/退回的判断沉淀为后续复盘和阶段成果的依据。

因此 `/learn` 新增并稳定以下 workspace 读模型：

- `contentJudgment`：材料专业性、阶段适配、本周角色、推荐片段、暂不使用原因和概念提示。
- `weeklyActionPlan`：本周最值得推进的几步，包含行动类型、为什么现在做、只看哪段材料、30 分钟起步且 15 分钟递增的预计时间、卡住时缩小策略。
- `nextAction`：本次最小推进，不要求用户先理解完整路线或补完整课程。
- `conceptHints`：概念默认折叠，用户点击才解释，避免前期术语过载。
- `learningOutputs`：accepted 或 needs_revision 的判断、产出和进展记录，作为连续周复盘的输入。

外部 AI API 的定位同步收窄：它是可选增强，不是 Trellis 能不能用的前提。可预期用途是解析用户粘贴的课程片段、生成更自然的概念解释、改写情景题和补充评审理由；正式学习状态、周计划、材料角色和证据裁决仍必须由 Trellis 的结构化服务与规则版 fallback 保底。

## 2026-08-29 内容池切片补强

为避免“课程推荐还是太粗”，内置资源映射不再只有一句 `usage`，而是补充为课程片段级判断：

- `segmentFocus`：本阶段只看哪一段，不要求读完整门课。
- `qualityRationale`：为什么 Trellis 判断这份材料专业可信。
- `skipGuidance`：当前先跳过哪些部分，避免新手被细节拖住。
- `learnerAction`：看完材料后要留下哪个判断或小动作。

`/learn` 的材料取舍卡会展示这些字段；行动卡标题也从底层活动名转为学习节奏表达，例如“先搞懂 / 看例子 / 做一版 / 判断题 / 小框架”。情景判断选项同步加长，帮助用户不用从零组织表达，也能留下更有信息量的轻反馈。

## 仍然保留的边界

- 暂不做账号系统、社交、课程市场、向量记忆或完整 MCP server。
- AI 模型接入只是增强项；无模型 Key 时规则版闭环必须可用。
- Mastra runtime 继续作为工程展示和 workflow runtime 层，不接管正式学习状态写入。
- 当前周 key 使用项目既有 `YYYY-Www` 逻辑；更严格的 ISO 周边界可在后续可靠性轮次处理。
- 跨周 action API 返回活动所属周 workspace；开始活动、提交证据、评审证据不会把用户跳回当前自然周。

## 2026-08-29 最终交付情景迭代

面向最终交付，`/learn` 需要呈现为“真实学习执行台”，而不是功能陈列页。本轮补强三点：

- 本周行动读模型加入节奏排序和小周主推进上限。小容量周优先展示 3-4 张主推进卡，其他活动进入补充推进或低精力备选；排序优先修订、待评审、进行中，再到本周主推进。
- 材料取舍区只直接展示最相关的 3-6 个材料，后续/参考材料折叠，避免用户一打开页面又被课程和资料淹没。
- 开始第 2/3 周活动时，`startActivity`、`submitEvidence`、`reviewEvidence` 都返回活动所属周 workspace，支撑“切到哪周就在哪周执行”的连续使用体验。

## 2026-08-29 Course Slicer 初版

参考 OpenMAIC 后，Trellis 明确不走“生成完整互动课堂”的路线，而是走“课程分诊与切片”的路线：判断材料是否专业，再切出此刻该看的片段，把它绑定到本周行动。

本轮新增 `courseSlices` workspace 读模型，不新增表：

- 每个 slice 包含 `resourceTitle`、`role`、`sourceRange`、`whyThisSlice`、`estimatedMinutes`、`learnerAction`、`afterWatchingPrompt`、`skipReason` 和关联活动。
- `weeklyActionPlan` 新增 `courseSliceIds`，行动卡不再只显示泛材料说明，而是能指向具体课程片段。
- `/learn` 新增“课程切片”区：本周必看片段直接展示，后续/参考/跳过片段折叠。
- 活动抽屉展示当前行动绑定的课程切片，用户打开行动即可看到“只看哪段”和“看完回答什么”。
- 规则版从已有内容包和用户资源摘要推导切片；外部 AI 以后只用于解析长课程大纲、字幕或 PDF，不作为基础功能依赖。

## 验收

新增 `npm run acceptance:three-week-loop`：

- 新用户完成诊断并确认首周计划。
- 用户材料映射节点后进入当前活动。
- 第 1 周短证据退回，修订后 accepted。
- 第 1 周复盘归档，并生成第 2 周。
- 第 1 周证据和活动状态在生成第 2 周后仍可读取。
- 第 2 周继续提交 hard evidence 并通过。
- 基于第 2 周生成第 3 周。
- 周历史可读取 3 周，刷新页面后仍能渲染。
- `/learn` 渲染课程切片和本周只看片段。
- `/learn` 无框架错误 overlay，无浏览器异常，并保存三张验收截图。

## 参考启发

- `mattpocock/skills` 的价值在于小型、可组合、可适配的 agent workflow，以及共享语言、TDD 和诊断反馈回路。Trellis 可以借鉴为“学习技能包/复盘技能/证据评审技能”的长期表达方式。
- `tt-a1i/archify` 适合工程架构、工作流、数据流和生命周期图；功能架构若面向产品讨论，draw.io 仍更适合快速表达用户旅程和页面职责。

## 2026-08-30 交付前三轮实现

本轮按“三轮交付计划”收束到可交付产品线：

1. Course Slicer v2：用户粘贴课程目录、视频目录、文章目录或摘要后，规则版会切成多个 `courseSlices`，并标记本周主线、后续再用、只作参考和暂不碰。高阶部署、微调、benchmark、数学证明等片段不会默认进入 AI PM 入门周计划。
2. 轻启动学习闭环：`/learn` 将计划历史折叠，反馈措辞从“作业”转向“轻反馈 / 小产出”，行动卡继续绑定具体 slice、30 分钟起步并按 15 分钟递增。
3. 交付包装：新增 case study、3 分钟 demo script、交付架构说明和 `delivery:precheck`，用于检查 README、部署说明、三周验收截图、hosting 配置和核心交付文档是否齐备。

当前产品判断保持不变：Trellis 的 MVP 不追求生成完整课堂，而是做学习内容整合、拆解和判断；外部 AI API 只作为长文本解析和表达增强，规则版必须能完成核心流程。

## 2026-08-30 Round 4-5 交付收敛

- `/learn` 第一屏从系统全景改成三块焦点：本次行动、本周只看、待处理。完整行动卡、材料取舍、学习产出、作品闭环和系统状态继续保留，但默认下沉或折叠。
- 活动抽屉优先显示当前行动绑定的课程切片和轻动作；长文本证据改成补充入口，只有作品任务才强调作品证据。
- `/workbench` 材料仍默认显示切片统计，全部切片改为点击展开，避免资源页变成另一面材料墙。
- 新增 `npm run smoke:production`，通过 `TRELLIS_BASE` 检查线上 `/learn`、`/workbench`、`workspace` API 和 `week-review` API；未设置线上地址时自动跳过。
- `delivery:precheck` 纳入 production smoke 脚本检查，部署 runbook 增补最终交付验证命令。
