# Trellis 收缩版 PRD：把核心功能做完整

日期：2026-09-12。状态：正式产品决策（经用户确认）。取代此前所有"扩范围"类提案的优先级；不推翻已确认的历史决策，只重排实施顺序。

## 1. 产品承诺（一句话）

> 给我一个学习目标和一堆课程，我告诉你先学哪几段、每段做到什么程度算完；材料不够时，我会直接告诉你做不到，并给出选择。

三句话边界：

- **做**：目标理解、材料取舍、路线编排、执行推进、反馈分流、状态诚实。
- **不做**：自制练习平台、生成式批改、领域内容生产、新工作流、新 Agent、新数据表。
- **教学外置**：内容来自原课程；Trellis 只负责编排与判断。

## 2. 为什么收缩

五维评审（`TRELLIS_PRODUCT_RUBRIC_2026-09-11.md`）证明：17 条真实模型路线 0 条可用，失败集中在一条链——**模型理解对了 → 求解器把核心目标挤进缺口 → 产品把残缺路线包装成完整**。修好这一条链，就是"完善功能"；其余一切都是这条链的装饰。

## 3. 唯一的根因与对策

代码定位：`curriculum-solver.ts`

1. 课程数量上限 `maxCourses=3` 在**核心节点还没选课之前**就锁死候选；前置基础节点先消费预算，核心节点全部落入 `uncovered`（H1/H2/H4 的直接机制）。
2. `deriveTargetNodeIds` 不区分"用户目标的核心节点"与"前置节点"，求解器无从知道哪些缺口是不可接受的。
3. 覆盖失败后没有诚实失败状态，`unresolvedGaps` 只是正文里的一段说明，路线照常发布。

对策：引入**目标核心覆盖质量门**——目标核心节点必须被安排；做不到时输出"有限方案"（planStatus=limited），明确说能做哪部分、缺什么、用户有什么选择，而不是照常发布完整路线。

## 4. 功能切片（按序交付，每个都有完成标准）

### 切片 1：目标→路线一致性 + 诚实失败（本 PRD 的核心）

- 求解分两轮：先为核心目标节点选课（预算可弹性放宽至 5），再为其余节点选课（预算 3）。
- 装配新增 `planStatus`（`complete` / `limited`）与 `coreNodeIds`；核心节点未覆盖 → `limited`。
- `limited` 时首屏呈现：能做哪部分、缺什么、三个选择（补充材料 / 缩小目标 / 调整取舍），不再冒充完整路线。
- 完成标准：H1/H2/H4 型输入的评测核心节点被安排进阶段，或路线明确标记为有限方案；新增保留样例回归通过。

### 切片 2：路线审阅与章节启动

- 首屏按用户决策顺序：我要解决什么 → 建议先做哪部分 → 为什么 → 投入 → 缺口影响 → 第一行动。
- 材料按"现在采用 / 之后可能需要 / 不相关 / 无法判断"摘要；比较按需展开。
- 完成标准：新用户 10 分钟内从输入走到第一个可执行片段；`locatorMissing` 时给出站内寻找指引而非留空。

### 切片 3：反馈分流与状态诚实

- 反馈按目的分支：完成未验证 / 测验通过 / 具体卡点 / 时间不足，四种处理不同。
- 自报不再转能力等级；起点诊断只在真实发生过时显示"已完成"；成长页只读正式路线。
- 阶段出口整合阶段目标，不再句式填空。
- 完成标准：五维表对 H1–H4 复评，目标维度全部 ≥1，无 0 分。

### 切片 4：恢复与调整（已有基础，做一致性收口）

- 刷新恢复、草稿/正式分离、调整差异预览（新增/删去/影响）跨页面一致。
- 完成标准：走查 14 项中 4 项失败全部转通过。

## 5. 明确不做（冻结）

C0–C10 课程内容包、雅思领域、领域图扩容、Mastra 新工作流、向量库、生成式成果批改、作品陈列室扩功能。这些是切片 1–4 全部验收通过之后的候选，不是现在的事。

## 6. 验收方式

- 每个切片：领域测试 + 固定样例 + 真实模型试验（保留集不调入参）+ 五维复评。
- 切片 3 完成后：本人真实使用三次（含隔日恢复），记录观察并修改复测。
- 不以自动化通过数量宣告放行；放行依据只有五维表与真人使用记录。
