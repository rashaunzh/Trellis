# Trellis 版本 12：实际体验复评与重建合同

日期：2026-09-13。评估对象：已发布 `61a2b08`，不是其他 coding agent 正在修改的工作树。本报告包含观察事实、产品判断及设计提案；设计部分尚未实现、未获真人验证。

## 1. 结论与此前判断的纠正

**版本 12 仍然像把内部学习编排对象展示出来的控制台，没有成为用户可以轻松开始、知道如何结束、反馈后知道下一步的学习产品。** 改善覆盖保护、草稿与状态可靠性是必要修复，但不足以称为用户体验重构。

建议重建主要操作层与交付规则：入口、路线审阅、当前任务、反馈、工作台和成长的阅读顺序不再受旧页面约束；复用持久状态、身份隔离、版本和确认机制。不是先删数据库或更换框架，也不是继续在旧卡片上增加解释。用户说“不如重建”是在质疑交付方式，本轮没有擅自执行破坏性重建。

上一份六任务交接把“尚待产品设计的问题”与“可直接编码的工作”混在一起。我收回把它视为完整产品交付合同的表述。产品分析、设计与验收结论仍由本任务 GPT 负责。

## 3. 当前产品的具体失败

| 编号 | 实际呈现或行为 | 为什么影响使用 | 应改变的规则 |
|---|---|---|---|
| V12-01 | 学习页在“开始这一节”之前依次呈现目标、缺口、统计、路线管理、周目标、周标准、停止条件、任务包 | 用户为了开始一项活动，要先阅读系统结构；手机操作位于多屏之后 | 当前任务与主要操作占据首屏，其他内容服务于当前决定 |
| V12-02 | 用户已写明确客服目标，页头仍说“先把模糊愿望转成可观察、可练习、可验证的能力目标” | 已提供的背景没有体现在主要叙述中，用户无法知道系统理解是否延续 | 当前任务承接已确认目标，不用关键词兜底模板重新描述用户 |
| V12-03 | 两个不同章节的停止条件都引用“判断何时需要 AI 的范围与主要范式” | 句子不构成可执行检查，也不能区分阶段和章节结果 | 每项要求必须明确对象、动作和可观察表现；未知检查能力明确标注 |
| V12-04 | 工作台显示“起点诊断：已完成”，本次从未做诊断 | 路线生成被冒充诊断事实，属于错误状态 | 诊断状态来自真实检查记录，而非存在路线 |
| V12-05 | “1 个可执行检查”下面是状态卡；另有一个“讲解与理解检查”链接 | 一个链接不能兑现所列起点、出口、复测的全部能力；不同检查没有独立承接 | 每个显示为可执行的检查必须可进入对应对象和要求 |
| V12-06 | 没有提交成果，仍显示“1 个成果状态”；内容是“还没有可评审成果” | 把占位对象计入统计，页面显得有能力而用户实际无成果可操作 | 空状态不计为成果，真实提交记录才进入列表 |
| V12-07 | 正式路线采用四门课程全部标“本周使用”，本周实际只有两项任务 | 路线层采用被投影成周承诺，增加用户对本周负担的误解 | 本周使用由本周任务决定；后续采用单独表达 |
| V12-08 | 已分流反馈仍把“理解、测验或卡点”放一起，同时提供感受、测验、情景题和片段状态 | 用户仍要自己选择内部处理方式，表达一次卡点需要理解整个表单 | 用此次发生的事情决定所需字段，系统根据规则承接结果 |
| V12-09 | 零材料启动后出现 26 门“后续与暂不采用” | 用户没有提供这些材料，却需要理解系统为何排除它们；后台候选搜索变成用户负担 | 默认只解释选定项及影响目标的缺口，候选全集作为按需依据 |
| V12-10 | 八周写在目标正文里，审阅仍主要是四段能力组和首周任务，没有完整八周安排 | 一条能力顺序不能兑现一条八周路线 | 周期必须进入明确合同；若尚未支持完整周期，不能只复述八周就视作交付 |
| V12-11 | 反馈后持久化、确认／拒绝与草稿恢复已有修复 | 这些是值得保留的可靠性，但不解决行动质量 | 把可靠性与产品结果分开验收 |

V12-04 的发布代码机制为 `buildTestMachine` 中“存在 curriculum → done”；V12-06 将空占位数组长度作为成果数量；V12-07 把路线采用项统一投影为 use_now。不是新发现了抽象风险，是页面与代码能够相互印证的现存问题。

## 4. 对标：Microsoft Learn 提供的最低交付标准

本轮选 [Microsoft Learn 的生成式 AI 模块](https://learn.microsoft.com/en-us/training/modules/what-generative-ai/) 作为“学习活动可执行”的参照。它公开呈现学习目标、前置和六个命名单元；点击 Start 可进入第一单元的实际内容。官方 [检查页](https://learn.microsoft.com/en-us/training/modules/what-generative-ai/5-knowledge-check) 提供与模块主题相关的具体题目与答题条件；模块概览说明账号通过标记需要登录及答题条件。这些是可核验的交付对象，不是“检查机”的概念说明。

| 用户问题 | 对标提供的具体对象 | Trellis 应交付的对象 |
|---|---|---|
| 我要学什么 | 模块目标与单元目录 | 当前目标、所选范围、为什么此时学 |
| 点开始后呢 | 实际单元正文 | 真实外部单元位置或可核验导航，不是再次解释任务 |
| 到哪里算结束 | 单元与具体检查 | 对应所选范围的停止条件及检查来源 |
| 怎样知道结果 | 答题条件与通过标记边界 | 完成记录、自报结果与独立评价的分别呈现 |

不照搬：Microsoft Learn 有自有内容且有 Microsoft 产品倾向；本次也未证明其题目足以评估客服方案设计等复杂能力。Trellis 组织外部材料，必须额外承担来源读取不足、账户/付费限制、不同课程重复、原检查不可用以及跨工具返回的问题。对标的价值是明确交付对象，不是宣称它解决所有学习需求。

## 5. 从新产品出发审视价值

目标用户不是泛指“所有想成长的人”，而是已有明确学习动机、材料选择困难、需要跨课程持续行动的自主学习者。真实任务应拆成四类：选哪些、怎么开始、卡住怎么处理、回来怎么继续。这是现有诉求支持的产品假设，不是市场规模已验证。

潜在替代方式包括直接跟随一个课程、请通用 AI 写计划、自己在笔记/任务工具维护进度。Trellis 必须证明额外处理材料与记录的成本，小于它节省的选课、找章节、判断卡点和重新规划的成本。没有这种净收益，更多自动化或页面不会产生持续使用理由。

首轮需求验证应让真实用户完成同一个学习任务，比较原有做法与 Trellis：是否少找材料、少重复解释背景、能否正确开始、回来是否无需重新规划。不要把用户说“路线看起来不错”算作采用价值；也没有证据现在就声称竞争壁垒或付费意愿成立。

## 6. 重新分配前台功能

以下为设计提案，保留工作台原有三类责任，不把它再次缩成只有材料。

- **学习**：用户日常回来首先继续的一项行动。首屏显示当前任务、实际材料入口、本次范围和结束后做什么；本周其他任务与完整路线按需查看。
- **路线审阅**：首次制定或主动调整时的决策页面，呈现目标、起点假设、时间、阶段与周安排、来源限制、首行动；采用后退出审阅，进入学习。
- **工作台**：材料、检查、成果三个有明确对象的操作区。添加材料能读到处理结果；检查能打开具体要求并提交；成果能新增记录、查看评价来源、修订与回读。生成式批改仍冻结，外部评价与用户记录不能冒充平台评价。
- **成长**：回看已确认路线、完成记录与证据。能力图是辅助视图，默认不让领域节点统计替代用户实际进展。

从界面撤下“学习处境编排”“任务契约”“测试机”“成果必须证明能力”等系统自述。不能仅换成亲切词：被撤下的说明必须由更少且更明确的实际操作接替。

## 7. 逐点击的交付合同

| 状态与操作 | 点击后应出现 | 保存／后续承接 |
|---|---|---|
| 新用户进入 | 单一“制定学习路线”；材料与成果独立入口仍可访问 | 有草稿时显示继续草稿，不重复索取背景 |
| 输入目标、经验、8/12 周及投入 → 继续 | 可编辑的目标解释；自报与未知起点分开；冲突项明确显示 | 只对影响安排的冲突追问；未确认不生成正式计划 |
| 粘贴链接／正文 → 分析材料 | 已读范围、能用于哪些目标、读取限制与采用建议 | 材料草稿可恢复；不要求先理解“来源中心” |
| 点击无法读取项 | 重试、补正文、排除或替代入口 | 只重试此项；其他材料和目标保持 |
| 点击查看路线 | 阶段结果、逐周预算、关键检查、缺口影响及首行动 | 默认折叠后台未选全集，仍可查看依据 |
| 点击修改某项安排 | 编辑相关范围及其影响预览 | 保存新草案，旧正式路线保持 |
| 确认路线 | 直接进入第一项任务 | 一次确认保存路线和首周安排，不二次确认同一选择 |
| 回到学习页 | 首屏：当前任务、材料位置、结束要求、开始／继续 | 路线统计不占据主操作前方 |
| 点击开始／继续 | 打开原单元；若只有主页，明确入口限制及经来源验证的路径 | 开始只记录行动位置，不认定完成；返回保持该任务 |
| 返回 → 记录这次学习 | “完成了／卡住了／这周时间不够／记录原测验结果” | 每个分支只出现必要输入，不让用户选择内部状态机 |
| 完成了 → 保存 | 保存完成记录，并展示下一项；没有独立评价则如实说明 | 不授予能力等级；有实际成果可附在该任务 |
| 卡住了 → 说明具体问题 | 引用该问题，给一个对应帮助入口；确需改路时另给调整预览 | 保存原任务与卡点，允许返回后继续 |
| 时间变化 → 看影响 | 本周哪些任务保留／延后、对阶段与周期的影响 | 确认才改周安排；拒绝保留原承诺 |
| 工作台 → 检查 | 对应任务、具体题目/外部检查位置、结果条件、提交入口 | 没有检查内容时显示未提供，不能显示可执行 |
| 工作台 → 成果 → 新增/修订 | 关联任务、正文/链接、版本、评价出处；可回看上版 | 保存实际成果对象；无模型评价不生成评价结论 |
| 阶段完成条件检查 | 本阶段结果、已有证据、未验证项、继续或补学选择 | 学完可以记录结束，但不自动证明目标达成 |
| 隔日进入 | 上次任务、位置、草稿或最近反馈，点击继续 | 手机与桌面使用同一正式记录；仅设备草稿须明确边界 |

首屏验收基准：1440×1000 和 390×844 均能发现当前任务与主要行动；展开完整路线不是开始学习的前置。不能只测试无横向溢出。

## 8. AI 机制应怎样支撑这些交付

1. **目标解释**：模型可提取结果与约束，来源必须是用户输入；不把未知基础改写为零基础，不把自报当诊断。自然语言与下拉值冲突先说明。
2. **材料证据**：明确目录可见、正文可读、原检查可用、访问条件和版本。标题只能支持有限判断，不能证明教学深度。
3. **选择与排序**：明确核心结果和真正阻塞的前置；先确保核心，仍须核对教学内容与顺序。节点覆盖不是充分条件。
4. **周期可行性**：把完整 8/12 周投入用于安排，分别考虑学习、练习、检查和修订；无法支持时解释缩小范围或延期的具体选择，不只生成第一周。
5. **活动编排**：每项产出实际入口、范围、结束要求和依据；内容不可用时返回材料处理，而非生成泛化停止句。
6. **反馈处理**：规则区分完成、卡点、原测验自报和时间变化；模型用于理解具体卡点或提出建议，不能越权改正式计划。
7. **调整**：证据、基准版本、前后变化与影响同时可读；确认后事务性保存；旧提案失效时保留用户输入并解释原因。

关键结论不能交给一次模型自评：发布时逐案例评目标、前置、材料依据、周期、任务执行与反馈承接，任何关键缺口不可用平均分抵消。当前无模型浏览器结果只足以否定交互与基线交付合格，不足以量化线上 Qwen 的最新质量。

## 9. 重建顺序与必须拿得出的成果

第一项交付应是“确认路线后，首屏完成一次真实学习行动”的新界面合同和可点击样本，再接现有真实状态；不是第七份抽象规划。样本用明确标注的真实来源示例，不能假装生成能力。检查能看懂且可开始后，再冻结对应 coding ticket。

| 顺序 | 必须交付 | 判定依据 |
|---|---|---|
| A | 当前任务首屏、路线审阅与四分支反馈的具体页面 | 与版本 12 截图并排比较；从确认到行动不再穿过系统说明 |
| B | 同一任务的真实材料、检查/结果、返回恢复链 | 浏览器动作与持久结果对应；检查及成果对象不再靠占位推导 |
| C | 8/12 周路线质量与动态调整 | 冻结案例与真实模型结果逐项评审；正式修改均需确认 |
| D | 工作台三个操作区及成长状态一致性 | 每个可用入口有操作终点；诊断、完成、证据不混用 |
| E | 所有者与首次使用者观察、修改、复测 | 独立开始、理解完成条件、恢复和反馈后继续；不是页面数量 |

现有 T1 agent 的求解/保留案例工作可以作为底层输入保留，但不再默认旧学习页结构已足够好。下一轮实现按本合同拆纵向票，每票包括所需状态、真实呈现、保存与异常承接；不把“加一个字段／改一个标签”当成功能交付。

## 10. 记忆与技能如何真正改变执行

- `domain-modeling`：根 `CONTEXT.md` 固定路线、阶段、任务、诊断、完成、证据和工作台含义。诊断不能再被“有路线”替代。
- `codebase-design`：让用户只需理解“继续学习／记录结果／查看调整”，把关联对象、版本和内部顺序收进可测试的实现；更少的用户操作承担更多实际工作。
- Matt 技能流程：已读取 `ask-matt` 路由；当前先完成证据与交付合同，再用可操作页面验证，再按 `to-spec`／`to-tickets` 定义独立纵向工作。不把 wayfinder 的“继续讨论决策”当作本轮交付，不重复要求用户替我们做课程设计。
- `writing-for-agents`：当前 handoff 只留当前状态、明确责任、有效证据与一个下一步；旧时间线保留为归档，不与当前指令并列。

部署责任仍由本任务承担。版本 12 是 ChatGPT Sites 托管发布；Worker/D1 是其技术栈，不代表已部署到用户自己的 Cloudflare 账户。用户本轮询问部署位置，没有授权迁移账户、切换身份或搬迁数据库，本轮不执行这些变化。
