# Trellis 内部测试计划

> 状态：中高级作品集验证基线  
> 日期：2026-09-02  
> 范围：本地内测，不面向外部公开用户

## 目标

证明 Trellis 不是课程推荐 Demo，而是能解决真实学习连续性问题的个人学习编排系统。

本轮内测只回答一个核心问题：

> 用户在材料过载、学习中断、来源不准和反馈后路线变化时，是否仍能清楚知道下一步该学什么、为什么这么学，以及系统保存了哪些判断。

## 目标用户

首轮只测试 AI / AI PM 初学者场景：

- 想理解 AI、生成式 AI 或 Agent 产品判断；
- 已经收藏了课程、文章或工具材料；
- 不确定哪些内容应该现在学、哪些应暂缓；
- 容易中断学习，回来时需要恢复上下文；
- 不希望学习系统变成新的打卡、日历或作业系统。

## 测试剧本

### 1. 首次进入与路线确认

输入：

- 目标：我想判断 Agent 产品场景，设计能力边界、人工兜底和最小评测方案。
- 材料：DeepLearning.AI 课程目录。

用户任务：

1. 打开学习页。
2. 理解系统推荐的是有限课程组合，不是完整课表。
3. 判断哪些课程被采用、暂缓或排除。
4. 确认路线。

通过标准：

- 3 分钟内能说出当前最小课程组合。
- 能理解“主线 / 选定章节 / 暂缓 / 排除”的区别。
- 能说出至少一个当前方案缺口。

主要观察：

- 用户是否误以为 Trellis 在推荐完整课程表；
- 用户是否找得到确认动作；
- 课程取舍理由是否足够可信。

### 2. 开始学习与来源定位

用户任务：

1. 在学习页找到当前片段。
2. 打开来源。
3. 判断来源是否能直达学习位置。
4. 在定位不够精确时补充准确位置。

通过标准：

- 1 次主要点击能进入学习来源。
- 用户能理解“只能到课程主页”和“个人补充的准确位置”。
- 补充定位后刷新仍保留。

主要观察：

- 来源精度标签是否降低信任；
- 用户是否知道补定位不会改变共享课程目录；
- 打开来源是否被误解为完成学习。

### 3. 中断恢复

用户任务：

1. 打开来源后不提交反馈。
2. 刷新或重新进入学习页。
3. 暂停当前片段并填写原因。
4. 再次进入学习页。

通过标准：

- 页面能显示“已打开未反馈”或等价状态。
- 用户能说出上次停在哪。
- 暂停原因可见。
- 下一步按钮语义明确。

主要观察：

- 恢复状态是否足够显眼；
- 用户是否知道应该继续、暂停还是补反馈；
- 暂停原因是否真的减少重启成本。

### 4. 反馈后变化可见

用户任务：

1. 对当前片段提交轻反馈或课程原测试结果。
2. 查看系统是否推进、保持开放、回看或插入前置。
3. 刷新后再次查看最近变化。

通过标准：

- 用户能说出变化来自哪条反馈。
- 用户能说出系统为什么这么调整。
- 反馈后的实际用时保留。
- 路线不会被静默重写。

主要观察：

- “最近变化”是否像解释，而不是日志；
- 用户是否信任低风险自动调整；
- 用户是否需要更明确的撤销或管理入口。

### 5. 工作台资料引用

用户任务：

1. 在工作台添加一条补充资料。
2. 将资料附加到当前片段或当前节点。
3. 回到学习页查看当前片段参考。

通过标准：

- 工作台能显示资源状态。
- 学习页能轻量引用当前片段资料。
- 用户能区分参考材料和候选课程。
- 工作台不承担路线管理职责。

主要观察：

- 用户是否把工作台当收藏夹；
- “已附加当前片段 / 已关联当前节点 / 可转课程候选 / 未整理”是否足够清楚；
- 资料是否增加整理负担。

### 6. 成果导向

用户任务：

1. 完成一个当前能力相关的小产出或判断。
2. 查看反馈后的结果总结。
3. 判断这条信号是否足以支持成长页的能力变化。

通过标准：

- 用户能说出本次学习获得了什么，而不是只说“看完了”；
- 用户能看到未证明的部分和下一步动作；
- 结果总结能区分能力信号与完整掌握。

### 7. 能力分叉

用户任务：

1. 使用不同目标或不同每周时间生成两份任务包。
2. 查看能力路径和相邻分支。
3. 解释为什么当前分支适合当前处境。

通过标准：

- 用户能区分路径方向和当前能力等级；
- 路径分支不是课程目录；
- 时间或目标变化会影响任务优先级，而不是只改变标题。

## 成功标准

本轮内部测试满足以下条件，才进入外部小范围测试：

- 5 条基础剧本与新增场景中至少完成 5 至 7 次手动内测记录；
- `npm run acceptance:internal-test-loop` 通过；
- `npm run acceptance:course-intelligence` 通过；
- 关键截图能支撑作品集叙事；
- 至少 3 个用户卡点被记录并形成明确取舍；
- 公开部署阻塞项仍单独管理，不混入内测结论。

## 不做

- 不新增第四主页面；
- 不展示多 Agent；
- 不做课程市场；
- 不做打卡、日历或每日任务；
- 不把工作台扩成完整知识库；
- 不以静态截图替代真实状态验收。
