# Trellis 周期路线与动态学习：分析及功能设计

日期：2026-09-11。状态：设计提案，尚未实现或验收，不修改已确认的个人路线与偏好。

后续修订：第5节八周AI样本主要是项目练习骨架，不足以作为课程路线蓝图。根据用户反馈，课程结构与详细交付合同以[课程专项调研](TRELLIS_CURRICULUM_RESEARCH_AND_DELIVERY_2026-09-11.md)为后续设计依据；保留本稿作为历史提案，不能据样本直接激活正式路线。

本轮要求：用户旅程必须细化到功能、点击、呈现、状态和异常；重点设计 AI／雅思等领域八周、十二周合理路线及动态调整。雅思用于检验跨领域设计，不代表当前正式产品已经支持雅思，也不以 AI PM 代表所有 AI 学习。

## 1. 产品承诺与评审方法

产品应交付：根据目标、起点、期限、投入和可用材料，提出有依据的周期路线；帮助用户开始实际活动、提交表现和成果，依据证据与现实约束提出可审阅的调整，并保存连续状态。

完整分析顺序：真实问题与替代办法 → 可观察结果 → 多入口用户旅程 → 每一步功能与交互 → 判断与数据约束 → 异常恢复 → 连续使用与成本验证。每个需求必须能追溯到一个用户任务，每个页面动作必须能追溯到保存结果和后续用途。

用户市场假设：有目标但缺少路线判断与持续执行支持的人，可能愿意为减少选择、组织、核验和恢复成本持续使用。本人的材料过载经历是需求证据，不等于群体需求、付费意愿或市场成立。后续需对比用户原有办法，观察首次行动、持续推进、结果质量及维护负担。

路线合理性逐项判定：目标是否真正覆盖；起点是否有依据；前置是否满足；活动是否有效且能开始；总周期是否容纳学习、练习、评价和返工；阶段出口是否可检查；来源是否可靠可用；调整是否保留目标和历史。任一关键项失败不能被平均分抵消。

## 3. 功能对象与边界（提案）

| 对象 | 用户含义 | 关系和边界 |
|---|---|---|
| 目标 | 在现实中想做到什么 | 有必达结果、可选结果、约束；不能仅存一句主题 |
| 起点证据 | 目前表现的依据 | 保存内容、日期、条件和来源；自报与测评分开，未知不是零 |
| 周期路线 | 在八周／十二周内怎样推进 | 包含阶段、各周重点、投入范围、出口、依赖、风险；不承诺必然达标 |
| 阶段 | 一个可验证的能力变化 | 可跨周、跨课程；不自动成为项目 |
| 项目 | 交付一项成果的容器 | 可贯穿多个阶段，并复用多项能力 |
| 周任务包 | 本周承诺推进的活动 | 有明确预算、核心和可选活动；非固定每日行程 |
| 活动 | 当前可执行的最小行动 | 必须有输入、步骤、输出、量规或完成标准、恢复位置 |
| 验证尝试 | 在指定条件下的一次表现 | 题目／任务版本、答案、条件和评价，不随重试覆盖 |
| 成果版本 | 用户提交的实际产出 | 外部链接或有限内容，绑定任务、评价、修订记录 |
| 调整提案 | 对正式路线的修改建议 | 有触发证据、差异、代价、版本和确认状态 |

学习页负责就地完成当前活动；工作台集中管理来源、验证与成果，并允许独立发起；成长页解释长期方向与证据。一个测试从学习页打开和从工作台打开，应进入同一尝试对象，而非另造一份记录。

## 4. 路线判别与生成：实际实现逻辑

### 4.1 先形成目标合同

结构化输入：领域与方向、目标结果、周期周数、是否有固定截止日期、每周可投入分钟、每次可用时段长度、已知不可用周、起点证据、材料与访问条件、语言与费用限制。普通用户先填少量关键项，其他随需要展开；每个追问必须能改变方案。

AI 领域先区分使用与判断、产品设计、应用开发等方向；不能把“学AI”直接解释成训练模型。雅思先区分考试类型、总分和各单项目标、考试日期、分项表现及测量日期。没有足够起点证据时可以生成暂定路线，但不得据此诊断已掌握或保证期限内达到目标。

模型提取用户意图及不确定项 → 用户修正摘要 → 保存目标版本。用户选“先看暂定路线”时同时批准使用界面列明的规划假设；假设不能进入正式能力结论。

### 4.2 使用领域内容包，不使用一套泛化评语

领域包至少有：成果类型、能力及前置、诊断任务、学习与练习模板、验证量规、材料目录与定位、投入估计依据、常见错误与补救、迁移和复测任务、版本与来源。

AI 产品方向评价问题定义、适配边界、证据、方案、评测等；AI 开发方向还需运行结果及代码／实验证据。雅思分听读写说；听读依据题目和答案，写作与口语依据不同维度。仅有口语转写不能评发音；没有可用录音评审服务时保留音频链接和外部评价入口，标明该维度未评。

官方依据：Academic 含听读写说；Academic 与 General Training 的阅读和写作不同，不能混用任务。写作评价涵盖任务完成／回应、连贯衔接、词汇和语法；口语还包含发音和流利连贯。AI练习评价不作为官方成绩。

来源：[IELTS考试结构](https://ielts.org/take-a-test/test-types/ielts-academic-test)、[官方样题](https://www.ielts.org/take-a-test/preparation-resources/sample-test-questions/academic-test)、[写作标准](https://ielts.org/cdn/ielts-guides/ielts-writing-key-assessment-criteria.pdf)、[口语标准](https://ielts.org/cdn/ielts-guides/ielts-speaking-key-assessment-criteria.pdf)。本文件的周计划是产品设计样本，不是这些机构背书的课程。

### 4.3 从终点倒推阶段与活动

终点成果 → 需要的表现 → 缺失能力及前置 → 阶段出口 → 学习／练习／产出／验证／修订活动 → 选择来源。已证实能力可减少基础活动；较旧或不匹配的证据需要针对性复核。

每个必达结果建立覆盖链：目标结果 → 阶段 → 活动 → 验证标准 → 来源或练习依据。核心目标没有覆盖时，不能把它放到缺口栏后继续宣称完整方案。可交付部分必须明确命名，并由用户接受缩小目标；未解决的先修缺口不得安排依赖它的高级任务开始。

同一来源可服务不同阶段，但不能以章节重复出现虚增学习量；复测可以重复能力，须改变或明确复用题目条件，避免把记住答案当迁移。

### 4.4 计算容量和可行性

周期可用时间 = 各周用户可投入时间之和。活动成本应包括阅读／观看、实践、验证、评价阅读和修订，不能仅使用视频长度，也不能把180分钟活动截成90分钟假装适配。

估计按15分钟粒度给范围，标明来自资料时长、领域设计估计或该用户历史。大任务拆为能独立留下中间结果的活动；未完成范围继续保留，不凭时长截断当完成。

初始可设置可见、可改的返工缓冲，例如八周每周6小时共48小时，先安排40小时活动、留8小时复核和修订。该比例是设计示例，需后续用实际投入校准，不作为学习规律。

系统同时检查总量、每周容量、先修顺序、单次时段、材料可用性和固定日期。返回三类结果：规划可容纳（不等于保证学会）、信息不足、当前约束冲突。冲突时比较延长期限／降低目标／增加投入的实际差异，不静默降低目标。

对八周切到十二周重新判断新增时间用途：加强薄弱项、增加迁移和复测或降低每周压力；不能机械拉长同一列表。由用户选择扩大结果还是减轻负担，不默认扩大范围。

### 4.5 分层规划与质量门

生成完整周期的周重点、阶段成果、预算和检查点；本周活动完全具体，后续周保留有依据的计划草案。用户能展开看远期预期活动与调整条件，不能只有“后续自动生成”。

模型负责提出目标解释、活动候选及理由。程序检查已知来源、目标覆盖、预算、顺序、可执行字段、版本、权限；领域量规判断语义适配。确定性规则也需产品评估，不能因其稳定就默认正确。

候选不通过时根据具体缺口最多进行有限次修复，仍失败则呈现阻塞原因及可操作选项，不无限等待。参考实现预算可设初次生成加一次修复；具体延迟和成本经真实运行后决定。

形成路线草案 → 展示检查摘要和关键限制 → 用户确认 → 同时激活路线和首周任务。后台保留输入、领域包、来源、模型／规则版本以及检查结果关联信息；前台只显示有助于判断的依据。

## 5. 两类路线设计样本

以下均为虚构设计输入，用于检验功能表达能力；未建立完整材料目录、未经过真人或学习效果验证，不可作为已完成的教学交付。

### 5.1 八周 AI 产品判断路线

假设：会使用通用AI，无编程基础，每周6小时；目标是完成一个范围有限的AI功能设计与评价案例，能够说明是否值得做、怎样验证、哪里需要人工介入。以个人任务整理场景为练习载体，真实用户需求需另行观察，不把合成反馈当用户研究。

| 周 | 核心变化与活动 | 必须留下的结果／检查 |
|---|---|---|
| 1 | 完成小情景起点检查；记录一次真实任务；比较现有办法与AI方案 | 问题定义和证据列表，区分事实与假设 |
| 2 | 学习相关AI能力边界；比较适合和不适合AI的案例 | 适配判断表，说明至少一个拒绝采用AI的条件 |
| 3 | 拆用户旅程、功能边界与异常；设计有限交互 | 一条可执行旅程，覆盖成功、失败、退出和恢复 |
| 4 | 用可访问工具做最小行为样本，保存输入输出 | 可重复观察的样本及局限；原型不得冒充完整服务 |
| 5 | 建立成功标准、错误类型和有限评估集 | 评价表，能区分关键失败与一般瑕疵 |
| 6 | 比较简单基线与AI方案；分析质量、等待和核验成本 | 对比记录和失败分析；合成样例明确标注 |
| 7 | 按失败修改功能／提示／交互，复测受影响范围 | 修改前后证据与剩余缺口，不只换文案 |
| 8 | 复核陌生情景，汇总案例和后续决策 | 成果评审及修订记录；解释支持哪些能力、哪些未证明 |

每周初始活动预算5小时，另留1小时缓冲；这是待细化的容量边界，只有首周和各阶段检查任务完全落地后才能确认可执行。阶段出口为问题与适配（2周）、方案与行为（4周）、评价与迭代（7周）、综合迁移（8周）。各周安排复习前期错误，而非知识学完即永久通过。

十二周版本可按1–3周问题与适配、4–6周方案与试作、7–9周评价和修订、10–12周迁移与综合成果组织；增加第二次陌生任务及修订机会。目标不变时不默认塞入Python、模型训练或部署工程。AI应用开发目标则需另设计可运行项目和必要编程前置。

### 5.2 十二周雅思 Academic 路线

假设：用户提供近期分项成绩，听6、读6、写5.5、说5.5；希望总分6.5且单项不低于6，每周8小时，固定12周后考试。先核验成绩条件与写说样本；下面只展示规划结构，不承诺提分。

| 周 | 主重点（四项保持接触） | 证据与调整检查 |
|---|---|---|
| 1 | 核对分项起点，做代表性任务并记录用时与条件 | 错误归类、写作样本、口语录音；缺项标未知 |
| 2 | 按起点安排听读理解练习、Task 2回应与段落、口语组织 | 逐项错误与修订证据，避免只背模板 |
| 3 | 延续核心弱项；加入Academic Task 1信息选择和概述 | Task 1与Task 2分开评，定位具体薄弱维度 |
| 4 | 同类新任务检查，观察能否迁移 | 与起点同条件比较，提出后续时间分配建议 |
| 5 | 集中补最影响表现的薄弱项；维持较强分项 | 补救活动后的新答案，非重复旧答案 |
| 6 | 听读分组限时练习、写作限时样本、口语互动练习 | 分开判断知识问题、表达问题与速度问题 |
| 7 | 连续任务训练和错因修订 | 时间内完成情况、重复错误及修订结果 |
| 8 | 一次具备足够覆盖的模拟检查，可按实际时段拆分 | 明确模拟条件；不等同正式考试成绩 |
| 9 | 按第8周证据调整弱项和维持练习比例 | 每项新增活动说明替换了什么及为何 |
| 10 | 陌生题材迁移和第二轮重点修订 | 检查表现是否依赖熟悉题目 |
| 11 | 再次模拟并复核明显波动 | 可比结果和未解决风险；不凭单次分数宣告达标 |
| 12 | 针对残余问题巩固、熟悉考试要求和回顾策略 | 保留限制说明和考前重点，不自动扩大内容范围 |

8小时周预算示例：听1.5、读1.5、写2、说2、周复核／缓冲1小时。写说时间包含完成、阅读评价、修订；其比例是初始设计假设，待诊断调整。模拟周替换常规任务并计入复盘，不额外叠加。

八周版本必须重新核对起点和目标。若投入不足，不能删除关键分项或评价来凑八周；给出按原考试日期聚焦备考的有限方案及其风险，或延长路线的选项。产品不能替用户更改实际考试日期。

## 6. 逐步交互规格

桌面1440：当前工作区为主，路线概要和依据可侧栏按需打开。手机390：单列，主操作就近呈现，长表转分项卡。以下名称是功能设计，不要求新增同等数量的一级页面。

| 步骤／界面 | 点击及输入 | 点击后的实际呈现 | 保存、下一步及异常 |
|---|---|---|---|
| 01 学习空态 | 点「制定路线」；也可「先整理材料」或「评审已有成果」 | 路线入口展示目标短表；其他入口不强制先建路线 | 保存入口上下文，材料／成果可稍后关联目标 |

| 03 目标理解 | 查看系统归纳；点「修改」更正；确认主方向 | 显示期末结果、必要澄清与暂不覆盖项，默认仅展开关键内容 | 点「确认目标」保存目标版本；不能把推断背景写成事实 |

| 06 生成 | 点「生成路线」 | 只展示真实状态，如核对目标／组织活动／检查安排；不编百分比 | 草稿与生成作业关联；刷新可恢复；取消后迟到结果不激活 |

| 15 阅读结果 | 点具体评价项查看引用；点「修改后再交」或「提出异议」 | 分项反馈、原文／答案依据、改进动作及未评部分 | 活动完成事实与能力评价分开；保留旧结果，修订产生新版本 |
| 16 学习受阻 | 点「我卡住了」选择位置并补一句说明 | 使用已有上下文提出针对性帮助，可选示例／缩小活动／补前置 | 若改变已确认活动，展示预览并点「采用」；不凭关键词自动加正式任务 |

| 18 调整审阅 | 点「查看调整」 | 对比新增／移除／推迟活动、周投入和阶段出口；显示证据与影响 | 点「采用调整」「保留原计划」或「修改建议」；拒绝不改正式状态 |

共享交互规则：每个状态一个明确主动作；不强迫阅读内部说明；展开依据后返回保留位置。表单错误定位字段，焦点跟随弹窗并返回触发按钮；键盘可完整操作，状态不能只靠颜色；加载、失败、空数据有不同呈现。移动端提交按钮不能遮住输入或错误。未来原型与浏览器验收按上述编号追踪。

## 7. 动态调整的判断、呈现与生效

调整输入应包括当前活动、原答案／成果、具体评价维度、近期可比表现、用时和用户说明、剩余时间、固定日期及来源变化。先区分能力缺口、材料障碍、任务过大、时间不足、目标变化和证据不足。

| 触发 | 应提出的建议 | 必须避免 |
|---|---|---|
| 一次没空完成 | 承接当前活动，询问是否只是本周变化 | 推断能力不足或全路线重做 |
| 连续同类错误且有可比证据 | 插入针对性练习与新题复测，替换低优先级活动 | 只重复原材料、只降低难度 |
| 表现超出当前要求 | 提议验证后跳过重复基础或转迁移任务 | 一题答对就跳过整个阶段 |
| 用户换目标／期限 | 对比目标覆盖和时间，形成新路线版本 | 改截止日期或丢核心结果不告知 |
| 材料失效或被排除 | 选择同目标替代材料，展示访问条件与活动变化 | 因缺资料删除目标 |
| 评价存在争议／证据不足 | 保留结论边界，补一次检查或接入外部评价 | 强行给精确能力等级 |

具体示例A：AI第5周成果把错误回复也计为成功。反馈引用其判定规则，建议修改成功标准并用新失败样例重评；从第6周可选阅读腾出时间，保留第8周综合成果。界面说明替换项目和原因，点击采用后才更新正式任务。

具体示例B：雅思第4周两次可比写作样本都未完整回应题目，而听读表现稳定。提议下周将30分钟可选听力转为审题与提纲修订，再用新题检查；总时长不变。若只有一次模糊AI评价，则先补样本，不据此大幅调整。弱项与时间分配需依据实际记录，不以此示例写死算法。

调整状态：候选 → 待确认 → 已采用／已拒绝／已过期；应用时核对正式路线版本、当前任务版本和目标版本。用户已修改目标或提交新成果后，旧提案先重新评估；不能覆盖新状态。已完成活动和历史评价不重写，撤回采用通过新提案表达。

AI产出先作为建议或评价结果展示。对正式路线、活动安排与能力记录的写入，遵循提案、审阅、确认；保存用户主动提交的答案与开始／暂停事实不另加重复确认。反馈页的「采用建议」可同时确认已展示的局部变化，避免多个无意义弹窗。

## 9. 功能实现切片与验收追踪

1. 先完善一个八周AI场景的领域样本、周期输入、覆盖和容量判断、路线审阅、首周活动合同。用已有成果／无基础／排除材料／期限冲突反例证明会作出不同安排；同步以十二周雅思样本检查通用合同，不在没有内容包时开放生产雅思入口。
2. 打通同一活动的开始、定位、作答／成果提交、分项反馈、修订和再次评价；工作台卡片直达同一对象。这是第一个完整纵向切片，不以“生成路线已好看”收尾。
3. 接入周复核、局部建议、正式调整对比和阶段验证，完成跨周恢复。再扩展领域活动覆盖，并验证完整十二周规划。
4. 冻结新保留样例，执行真实模型、浏览器和真人连续使用；曾用于修复的H1–H4不得继续作为未见验收集。不得用本文设计样本冒充模型结果或真人反馈。

| 验收情景 | 检查点 |
|---|---|
| AI八周，无编程基础 | 路线核心成果有活动与评价；不无依据加入编程前置；首项直接可开始 |
| AI已有成果 | 起点证据改变活动安排；评测目标不能再次被排成缺口 |
| 十二周切八周，固定周投入 | 明确目标／时间取舍；不能只改标签或把活动时长截短 |
| 雅思分项不均衡 | 不同起点产生不同分配；写说评价与听读判题分离 |
| 来源仅主页或无法读取 | 不虚构章节；提示实际可执行替代或补位置；保留原目标 |
| 提交后评价失败 | 原成果已保存且可恢复；重试评价不重复提交 |
| 连续证据触发调整 | 对比有实际活动差异、预算和出处；拒绝不变；确认持久生效 |
| 改路期间出现新反馈 | 旧提案过期／复核，不能覆盖新的正式事实 |
| 阶段结束但验证未过 | 显示具体未过项和复测入口；不按读完课程判掌握 |
| 多日回访与跨标签 | 找回位置、输入和结果，正式路线一致，冲突可处理 |

工程复用D1、身份隔离、已有来源版本与正式／草稿机制；修正现有服务边界和合同，避免新增平行运行时。是否需要迁移表结构，应以一个完整切片的数据生命周期为依据，不能先扩架构再找需求。
