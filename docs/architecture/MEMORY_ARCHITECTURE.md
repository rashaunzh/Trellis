# 协作记录、个人资料与运行状态

更新：2026-09-14。

## 三类数据的责任

| 内容 | 位置 | 版本管理 |
|---|---|---|
| 产品业务状态 | D1；本地开发状态在 .wrangler/state | 不提交运行数据库 |
| 产品决策、项目进展与交接 | docs/、memory/decisions、memory/handoff | 可审阅、简明记录后提交 |
| 个人偏好和长期路线 | memory/profile、memory/routes | 本地保留，Git 忽略 |

个人文件可供当前设备上的协作者按需读取；新克隆不以这些文件存在为前提。需要跨设备同步个人资料时，应单独确定私有存储位置和权限，不重新混入产品交付树。

## 协作流程

开始前同步 Git，读取当前交接、产品契约与实现状态。具体界面工作再读桌面设计对应章节。个人需求相关时，可选读取本地偏好与路线；缺失时不虚构用户事实。

结束前更新进展和交接，新增一份简短工程会话记录。项目记录只保留目标、变更、验证、边界与下一步，不复制私有对话、求职材料或本机路径。

设计建议与已确认决定分开；对个人路线和偏好的实质修改仍需提出建议，不能静默改写。

## 历史与发布

普通 Git 删除只改变当前树，不删除旧提交。仓库原来保存过个人资料，因此本次退出版本管理不能证明历史已可公开。保持私有；改可见性或重写历史必须另外明确授权并验证。

.env.local、.dev.vars、Cookie、令牌和个人运行数据库始终不进入交付材料。公开审阅前须区分源码审阅、Git 历史、Release 附件、Actions 产物及网站运行数据。
