# 核心重做验收入口

本入口实现用户批准的五轮测试计划。自动检查、模型尝试、产品评分和真人使用分别记录；目前不满足放行条件，不能称为“核心流程已验收可用”。本次实际结果见[执行记录](TRELLIS_REDESIGN_ACCEPTANCE_2026-09-10.md)。

## 执行方式

在仓库根目录，使用 Node 22.13+ 和已安装依赖：

```powershell
npm run acceptance:redesign-core
npm run acceptance:redesign-core -- --phase=judgment --include-holdout
npm run acceptance:redesign-core -- --phase=browser
npm run acceptance:redesign-core -- --phase=model
npm run check
```

默认按 judgment → browser → model 顺序执行，遇到失败或待验收停止。`--phase` 用于分别收集诊断证据，不构成跳过前轮的正式验收。原始 Node 脚本退出码：0 为该轮要求通过，1 为自动检查失败，2 为缺环境或人工证据；npm/PowerShell 可能将非零统一显示为 1，应以 `result.json` 为准。人工部分没有填完时返回非零是预期行为。

每轮在 `outputs/redesign-core/<时间>-<轮次>-<进程号>/` 新建目录，保留逐项结果及耗时。浏览器额外保存截图、API 请求路径/状态/关联 ID（服务未提供则为 null）、迁移日志、服务日志和隔离数据库。原始输出不提交 Git；需要跨设备评审时应转移整个运行目录，保留原文件和哈希，不能只挑成功截图。

浏览器使用现有 Chrome 查找工具和安装的 Playwright。默认使用 Codex 自带依赖路径，可通过 `TRELLIS_PLAYWRIGHT_PACKAGE` 指定包含 Playwright 的 package.json。每次启动独立 localhost 服务、独立 owner、独立 Wrangler 配置和 D1 状态目录；只执行本地迁移。不会接入个人开发数据库。通过环境变量 `TRELLIS_ACCEPTANCE_CONFIG` / `TRELLIS_ACCEPTANCE_STATE` 向 Vite 注入本轮配置，不新增公开产品 API。

模型轮读取已有 `.env.local` 配置，仅发送合成输入。缺主模型配置会明确阻塞，不以基线输出冒充真实模型。20 个计划试验每次使用独立内存仓库，避免重复样例命中缓存；业务时间冲突会在模型前被拒绝，实际模型次数与计划试验数分开记录。反馈当前仍为规则策略，输出的 `feedbackMode` 明确标注这一点。

## 判断样例与评分

[cases.mjs](../../scripts/acceptance/redesign/cases.mjs) 冻结 8 个开发样例和 4 个保留样例。各例包含输入、允许判断、禁止结论、证据和需要核对的约束。首次开发检查不执行保留例；只有显式 `--include-holdout` 或真实模型轮才读取保留例。H1–H4 已在 2026-09-10 首次验收运行中使用；若后续依据这些结果修改判断逻辑，须将它们标为已消耗并补充新保留集。

输出 `outputs.json` 和 `review-template.json`。评审者复制模板为同目录 `review.json`，逐项填写目标适配、阶段递进、取舍依据、任务可执行性、反馈匹配：0 不成立、1 需修改、2 可用。每项填写准确输出位置与判断依据；未读正文不能当作事实依据。所有项必须为 2，不计算平均分。

```powershell
npm run acceptance:redesign-core -- --phase=judgment --review-run=outputs/redesign-core/<运行目录>
```

判断轮复核会核对源码指纹、样例哈希、原输出哈希、自动检查及逐项评分。旧输出缺源码指纹或代码已经变化时，必须重跑。真实模型轮的模板按“样例/重复次数”分别评分，不能用最好一次替代其它结果；当前尚无模型评分自动合并与最终放行命令。`releasePassed: false` 是保守的报告状态，不是可手动修改为 true 的审批开关。

## 覆盖边界

| 要求 | 实现与证据 | 不能据此证明 |
|---|---|---|
| 阶段区分、章节取舍、约束 | judgment 的 45 项结构/约束检查 | 五维语义质量全部可用 |
| 两条用户主链 | browser 的 zero / materials，通过 UI 写入并读回 | 真实身份登录、长期效果 |
| 刷新、重启、位置、跨周 | 浏览器恢复及真实 SQLite 重开、SQL核对 | 远端 D1 跨进程并发一致性 |
| 重复点击、响应丢失、旧标签页 | recovery 注入网络失败并读数据库计数、409 | 所有数据库写入中途故障均原子恢复 |
| 取消生成、拒绝调整 | 延迟真实响应、拒绝后检查正式路线不变 | 页面关闭时所有后台工作都被取消 |
| 不同用户读写 | 浏览器读取隔离、SQLite 服务读写拒绝 | 托管登录身份与线上授权配置 |
| 无模型、超时、格式错误 | 新领域失败注入测试及真实模型全部尝试 | 每次模型调用均成功 |
| 材料读取失败、不可读取正文 | 复用 content-analysis / source-fetcher 测试，标题样例保持未知 | 当前全部外链内容已重新核验 |
| 手机、键盘、反馈可读性 | 390px 无横向溢出、焦点/Escape、截图；移除内部编号/百分比，回显本次笔记 | 完整键盘可达性审计、真人理解时间 |
| 阶段收口、能力与完成区分 | 完成点击不认定掌握；跨周提案保持待确认 | 完整阶段迁移应用、延迟复测达标 |

数据库中途故障已覆盖“反馈已存、行动投影未写完”的恢复；其它写入边界及跨进程并发、完整阶段能力出口仍需验证。生成中刷新检查覆盖“服务已存草稿、浏览器尚未收到响应”窗口，不覆盖强杀正在写入的服务。测试脚本的通过数量不覆盖这些空白。前述缺项、真实模型反馈和五维评分没有解决前，不进入正式放行。

## 真人观察（当前未执行）

使用[观察记录模板](TRELLIS_REDESIGN_HUMAN_OBSERVATION.md)，由所有者完成至少三次任务、两种活动类型和一次隔日恢复；另请一位未参与开发的人做首次走查。可记录匿名参与者代号，不记录敏感材料。

观察者先不给操作指导：5 分钟时请参与者用自己的话说明阶段目标、下一步、完成标准和暂时不用做什么；10 分钟内记录是否开始真实活动。分别记录生成等待和找入口/理解界面耗时。遇到阻塞可以帮助，但必须记录帮助发生的位置，不能算独立完成。

至少完成一次观察 → 修改 → 同场景复测，再评审放行条件。私有部署后用真实身份验证保存、退出重进和恢复，不能用本地匿名测试身份代替。长期学习效果持续观察。
