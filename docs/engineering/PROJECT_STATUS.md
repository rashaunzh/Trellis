# Trellis 当前实现状态

更新：2026-09-16。此文件是当前进展的唯一入口；实现事实基于源码与已记录验证，设计交付单独说明。

## 产品处于什么阶段

目前有可运行的学习编排功能底座：输入目标与材料、生成候选路线、确认活动、记录推进和反馈。尚未完成桌面端统一交互，更不能把测试通过称为正常产品体验或真实学习效果已经达标。

[产品设计决策](../product/TRELLIS_PRODUCT_ANALYSIS_2026-09-14.md)和[桌面交互规格](../product/TRELLIS_DESKTOP_UPDATE_DESIGN_2026-09-14.md)已重写为学习辅助闭环版。用户明确流程清晰和辅助学习价值优先，点击数量不是主要目标。旧 CK 表退出当前实施依据，保留于 Git 历史。

2026-09-15 再补完整性标准与可实施规格：9 项门、10 条需求追溯、四个学习/材料产品的一手证据、界面内容分层、固定页面职责和路由、原子控件登记、同一学习样例的连续内容稿、迁移与 22 个验收情境。原子控件登记是设计清单，未逐项实现；连续内容稿不是可操作原型。现可支持完整优化设计和分包评审，仍须完成原型、新手试用与真实模型质量验证，不能宣布整体设计有效或页面优化已完成。

下一包 P0 改为一个支持主题的“导学—学习—尝试—反馈—修订—收尾”完整过程，包含保存与恢复；不再以活动列表加完成按钮作为首包完成标准。现有 learning-program、program-bindings、scenario-bank 可提供有限基础，但内容质量、开放回答反馈、修订关系与会内恢复仍需审阅和实现。未新增业务代码或线上验证。

## 完成程度如何判断

不用一个缺少分母的百分比概括产品。分别判断：

- 产品边界：已有当前契约，明确外部课程教学、AI 提案和用户确认。
- 设计交付：可实施规格与验收标准已写出；连续可操作原型和真实新手理解尚未验证，P0–P4 桌面包与 P5 手机包均不能据此算实现验收完成。
- 功能实现：主链条各环节已有代码，部分本地操作可运行；不是全部新设计点击均已实现。
- 体验验收：当前截图显示实际界面，确认了首次路线到反馈面板的路径；尚未验证完整成果提交、长期恢复和所有异常分支。
- 上线与用户效果：本轮未部署、未重新验证线上身份/数据，没有真实长期学习效果证据。

## 下一步按可交付切片推进

1. **P0 一个主题的完整辅助学习。** 先按桌面第 20 节做同一样例的连续可操作页面，核对第 19 节控件与第 23 节核心分支；审阅目标、例子、任务、量规和帮助的一致性，再实现学习空间、尝试、具体反馈、用户修订、收尾和恢复。现有 ai-boundaries 包没有全部新标准，开放反馈和回退标准不能当现成能力。复用已有服务，不以换名的旧表单代替。
2. **P1 从目标到合适起点。** 在路线审阅中明确每项活动实际支持的辅助范围、来源与缺口；确认结果可恢复。
3. **P2 基于表现继续。** 修订、新情境表现和未处理问题连接成长、复习、路线调整与周安排；正式变化审阅后生效。
4. **P3 扩展材料与支持主题。** 每个新辅助包经过同样内容质量与模型评价门，补齐材料版本、运营和成本验证。
5. **P4 桌面整体与真实试用。** 验证流程理解、反馈可执行、修订改善、错误恢复与多设备；不能仅以点击数和截图验收。
6. **P5 手机专项。** 桌面验收后适配相同学习链的小屏操作。

每个切片交付应包含：对应点击编号、实际页面、前后状态、可复现测试和剩余限制。不能仅增加字段或组件后宣布功能完成，也不应为界面整理先重建数据库与工作流。
