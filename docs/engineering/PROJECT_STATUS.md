## 完成程度如何判断

不用一个缺少分母的百分比概括产品。分别判断：

- 产品边界：已有当前契约，明确外部课程教学、AI 提案和用户确认。
- 设计交付：详细桌面规格已写出，六个桌面交付包与后置手机包尚不能算实现验收完成。
- 功能实现：主链条各环节已有代码，部分本地操作可运行；不是全部新设计点击均已实现。
- 体验验收：当前截图显示实际界面，确认了首次路线到反馈面板的路径；尚未验证完整成果提交、长期恢复和所有异常分支。
- 上线与用户效果：本轮未部署、未重新验证线上身份/数据，没有真实长期学习效果证据。

## 下一步按可交付切片推进

1. **桌面活动闭环优先。** 合并重复的任务显示，完成同一活动列表 → 详情 → 打开外部课程 → 返回 → 完成/暂停/需要帮助 → 下一项。复用已有状态与接口。验收包含刷新恢复、重复提交、无章节直达、失败重试；完成记录不得自动变成能力掌握。
2. **首次设置和路线审阅。** 用同一真实长度样例贯穿新用户、无材料、部分路线、修改约束与确认；确认之前只能是候选，不写正式计划。
3. **帮助与材料。** 按反馈意图区分输入和结果；完成材料分析失败恢复、片段审阅与采用。让用户知道下一步可以做什么。
4. **成长、调整和跨周。** 对齐覆盖/执行/证据三类指标，呈现变更前后和影响范围，确认后再改变计划。
5. **桌面统一验收。** 对照设计第 14 节的交付包和验收流程，验证加载、空状态、错误、取消、返回、刷新、键盘及长内容。完成一包再开始下一包。
6. **手机专项最后。** 桌面闭环验收后才推进移动导航、触控和小屏信息重排。

每个切片交付应包含：对应点击编号、实际页面、前后状态、可复现测试和剩余限制。不能仅增加字段或组件后宣布功能完成，也不应为界面整理先重建数据库与工作流。
