# 发布与线上验收

更新：2026-09-14。本文件描述发布步骤，不把历史部署结果当作当前线上验收。

## 部署形态

当前采用 ChatGPT Sites 托管的 Worker 与 D1。复用 .openai/hosting.json 的非秘密绑定配置；不根据占位符猜测远端数据库 ID，不改用直接 wrangler deploy 替代托管流程。

仓库代码更新、构建成功、网站部署、数据库升级、真实登录验收是不同事项。GitHub 同步不会自动证明网站已经更新。

## 发布前

1. 固定待发布源码 SHA，并确认干净工作区。
2. 执行 npm run check、npm run delivery:precheck、npm run validate:artifact。
3. 检查构建包只含 dist 等正式产物，没有个人记忆、.env、.dev.vars 或运行数据库。
4. 核对真实目标环境、访问范围、DB 绑定与已应用迁移。以 migration-manifest 为顺序依据。
5. 迁移前确认数据备份与恢复方式；代码回退不等同数据库回滚。
6. 配置托管身份与必要的服务端模型变量；秘密只进入平台 Secret。
7. 发布已保存且已核对的版本，记录源码 SHA、平台部署标识和环境版本。

## 生产身份

由可信托管入口注入身份，服务端校验模式与精确主机范围。本机 x-trellis-owner-id 仅供开发。伪造邮箱 header 的脚本不能替代真实用户登录测试。

## 线上必须验证

- 真实获准用户可完成材料、路线确认、活动、反馈和恢复。
- 未获授权身份不能读取数据；第二个获准身份验证隔离。
- 数据迁移保留原记录，新表与业务状态可用。
- 真实模型调用、失败降级和来源限制符合预期。
- 已确认路线修改先预览确认，网络重试不重复产生事实。
- 核对实际页面版本，避免拿旧网站地址作为新版交付。

本次仓库整理没有执行部署、线上迁移或扩大访问范围。当前线上状态应通过发布平台单独核验。
